日期：2026-09-24。状态：供讨论的美术提案，尚未冻结；不修改玩法、数值或现有客户端。

样板由内置 image_gen 生成并做一次现代化版式修订。它展示视觉气质，不是实机截图；图中的透视、灯光、地图连线与状态符号仍需在正式界面稿中精确校准。[原始提示词](../../output/art/joy-art-board-v0.1-prompt.txt) · [修订提示词](../../output/art/joy-art-board-v0.1-refinement-prompt.txt)。

## 1. 核心方向

**深空星图、现代城市怪谈、专业公司的调查档案。**

玩家从宏观上看见一座像星图般展开的异常城市；进入现场后，看到可信的旅馆、医院与地铁空间；公司建立的营业点形成稳定、温暖、可以依靠的小片秩序。

建议将“宇宙星系”作为全游戏共同的视觉语言：深暗空间、微小光点、疏密分明的连线、缓慢变化的星尘、精确而克制的文字。城市地点仍然有建筑、门牌、地铁标识和真实生活物件。玩家的身份始终是经营异常回收公司的老板。

工作名称可以叫“星图中的异常城市”，仅用于交流美术方向，不新增世界观设定。

## 2. 参考依据与本提案的边界

用户指定参考：[OpenAI GPT-6 Astra 页面](https://openai.com/zh-Hans-CN/index/gpt-6-astra/)。本次能读取页面正文，但浏览器视觉页面被人机验证拦截，未实际核对首屏完整画面和动效。

因此，以下配色、构图、材质与动效均为基于用户“宇宙星系风格”描述的原创提案，不声称是官网的准确提取或复刻。获得参考截图或可查看页面后，再核对用户最喜欢的具体部分。

玩法约束参考已整理的 [Wiki](../wiki/README.md) 及 [需求 v0.3](../requirements/Joy_需求规格说明书_v0.3.md)，延续既有城市节点经营、手操探索和卡牌系统，不用美术新增尚未确定的机制。

## 3. 玩家应感受到什么

| 时刻 | 目标感受 | 主要表现 |
| --- | --- | --- |
| 打开游戏 | 安静、巨大、未知 | 深暗画面，一条隐约的星尘弧，少量城市灯光和简洁标题 |
| 浏览城市 | 可以规划、存在危险、业务正在生长 | 可追踪的地铁网络、明确的地点轮廓、持续保留的公司网点 |
| 进入现场 | 这地方很普通，但某处不对 | 日常建筑与物品，局部透视、反射、阴影或时间关系异常 |
| 推理成功 | 从不确定中建立可靠知识 | 档案确认、线索关系清楚、反馈短而明确 |
| 网点营业 | 自己建立了秩序 | 稳定的窗灯、公司标识、明确营业状态和员工驻站 |
| 异常扩张 | 已建立的秩序受到压力 | 根据已公开信息出现的边界变化、传播箭头与设施状态 |

整体不依赖频繁惊吓。美感来自广阔暗场与细小秩序的关系；恐怖来自可信现实里的局部矛盾。

## 4. 配色与材质

以下为首轮试色值，不是官网取色结果，也不是已验收的最终颜色。

| 颜色 | 试用值 | 用途 |
| --- | --- | --- |
| 深空底色 | `#080C15` | 大面积背景、地图空白 |
| 深石板色 | `#171E2B` | 不透明信息面板、卡牌文字区 |
| 暖灰白 | `#E9E6DE` | 主要文字、清楚的细线和图标 |
| 冷青色 | `#8CBAB7` | 公司连接、选中状态的辅助提示 |
| 灰紫色 | `#9A91AF` | 已展示的异常现象和少量氛围 |
| 灯光琥珀 | `#D3AD6B` | 营业窗灯、现场灯具、人的活动痕迹 |
| 暗珊瑚红 | `#C66D70` | 明确警告、已发生伤害、失效标记 |

画面大致以 75% 深暗底、20% 中间明度内容、5% 高亮为构图起点。该比例用于控制画面焦点，不要求文本和必要操作区刻意变暗。

背景可用稀疏星尘、细颗粒、微弱光晕；文字区使用稳定实底。建筑采用低饱和的半写实绘画，木材、玻璃、金属、纸张各有清楚质感。按钮、路径和图标保持干净，避免用整屏玻璃模糊削弱文字。

颜色必须与形状、图标或文字并用。琥珀灯光表示具体灯具或营业状态时必须有对应标记，不能单靠“暖色”保证房间安全。

## 5. 城市地图

### 构图

城市底图以低对比的街区、海岸或楼群轮廓提供空间感，星尘沿空白区域展开。地点形成星图般的节点，但节点中心保留建筑剪影；地铁线路连接地点，视觉上始终能追踪来路与去路。

大地图保持经营桌面的稳定感。占领过的节点保留公司牌匾、设施和营业信息，避免看起来像经过后就消失的单次关卡。

当前 M2 画面可直接用总部、暮灯旅馆、北街枢纽、白榆医院、红箱源头、南街枢纽、公共协作点做样例。它们的真实相邻关系以 [地点百科](../wiki/locations.md) 为准；氛围图不作为地图拓扑验收依据。

### 信息分层

| 信息 | 建议画法 | 不混用的含义 |
| --- | --- | --- |
| 地点类型 | 中央建筑轮廓与名称 | 不表示是否占领 |
| 公司已接管 | 独立公司牌匾或完整产权框 | 不表示已经营业 |
| 营业资格 | “营业中”“明日生效”“缺少驻站”等状态 | 建成、有人、连通等条件分别可查 |
| 队伍位置 | 独立队伍标记，含队伍编号 | 不替代节点的公司归属 |
| 当前选中 | 外围中性选择框 | 不充当异常范围或营业状态 |
| 可通行路径 | 稳定实线，线路名可查 | 装饰星线不进入可操作地图 |
| 中断路径 | 明确缺口与断路符号 | 不只降低亮度 |
| 已知传播预告 | 指向具体目标的箭头与文字 | 与真实道路、运输动画分层 |
| 有效封控 | 横跨边的封条或阻断符号 | 不承诺整条线路绝对安全 |

装饰星点应比节点小、暗且无同形边框。看起来可点击的对象必须有实际交互。多人/多队并行调度时，任务与工具预留放在清楚的事务卡槽里，不靠地图粒子表达占用。

## 6. 现场探索

建议采用固定视角的 2D 场景插画与清楚的房间导航。用少量分层、灯光和局部动画增加深度；无需为了风格先扩展为完整 3D 漫游。

| 场所 | 日常基础 | 可用于美术概念的异常意象 |
| --- | --- | --- |
| 旅馆 | 暖色壁灯、木门、门牌、前台和旧地毯 | 镜中走廊的尺度不合理，某个倒影出现极深的星尘空间 |
| 医院 | 灰白瓷砖、金属推车、病历柜、冷色灯 | 柜后的暗部像没有尽头，反射中的走廊轴线轻微错位 |
| 地铁/枢纽 | 导视、站台、闸机与路线图 | 在内容获知后，线路与远处光点出现不自然的延伸 |
| 公司总部 | 档案、封装柜、任务板和统一标签 | 光线稳定、日常功能清楚，让公司管理成为秩序来源 |
| 异常源头 | 仍能辨认原先用途的城市空间 | 更大范围的空间断裂和视差异常，重点物品仍可识别 |

以上是气氛母题，不是新增规则证据。例如，画中的镜面星尘不能让玩家无须调查就辨认镜中住客 A/B。实际线索、规则触发、敌影出现必须按玩法状态决定。

场景可以令人不安，操作信息必须可靠。出入口、当前房间、可交互对象、行动费用和撤离入口不因演出消失或漂移。

## 7. 卡牌、实物与人物

### 卡牌

卡牌采用公司的“行动档案卡”形态：上半部是一个清楚主体，下半部为平静、留白足够的效果区；费用、目标、条件和耗尽标记位置固定。用细线、编号和极少量辉光连接星图主题。

首轮样例选三张足够：调查使用文件与聚焦光束，点灯使用实际灯具，模仿使用错位的重复轮廓。具体费用与效果由正常 UI 排字；生成插画不承担正式规则文本。

同轮使用卡后原槽留空，其余牌不自动挪位。模仿需要独立、可读的“参考：某行动”提示；疾走后该提示保持，当前目标按实际位置更新。动效体现指令作用于当前目标，不能表现成复制上一份实物奖励。

### 异常物与工具

物品首先是可信的日常实物：座钟、灯、样本瓶、封装箱。异常感来自细节、反射和空间关系；隔离工具用工业材质与统一的公司标签。

同一物品从现场、入包、封装、归库到交付始终使用同一主体缩略图。封装增加封条或容器叠层；安装增加位置状态。只在实际交付或出售入账时播放现金反馈。

### 员工

先采用克制的工作证头像或统一半身剪影，以外套、工牌、手套与便携工具建立公司身份。岗位使用可替换图标，人物造型不暗示尚未实现的职业技能或战斗属性。避免在第一轮风格验证中投入大量独立立绘。

## 8. 信息可信度与可读性

- 观察事实、候选推测和已确认规程使用不同档案标记；未经确认的同类规则保留相同视觉底层，避免隐藏答案通过纹理和颜色泄露。
- 运输只显示已知后果；未知时写明未知，不能使用绿色安全盾或“零风险”图形。
- 城市“第几经营日”和现场“第几轮 / 剩余行动 / 封门期限”分开显示。浏览菜单不播放时间推进反馈。
- 左侧状态与目标、中间场景、右侧常驻预览、下方固定手牌槽作为初版布局基础，具体比例以后在真实文本下调整。
- 文本、费用与危险提示放实底上；1080p 下正文可先以 18–20 px 试排，支持放大，并用最长中文内容实际检查。
- 图标要在灰度图中仍能区分；辉光和细描边不是唯一的可见边界。
- 预览、实际结果和日志保持对应；护符抵挡要有独立反馈，避免“心志没掉”被误认为没有触发异常。

## 9. 动效语言

| 元素 | 建议表现 |
| --- | --- |
| 背景星尘 | 缓慢、小范围，避开文字，不承担玩法计时 |
| 选中节点 | 短暂聚焦后稳定，不持续闪烁 |
| 建立网点 | 公司标记落位；到真实生效时点才切换营业灯光 |
| 调查确认 | 档案确认标记与一条简短反馈，保持证据可回看 |
| 模仿 | 短暂复制行动符号，连接到当前目标 |
| 伤害与护符 | 对应目标处短促变化，随后保留可读结果 |
| 异常传播 | 日结时按已公开预告表现传播与封控结果 |
| 日结 | 依次展示收支、工程、扩张与交接结果，能跳过演出查看明细 |

所有装饰动效提供静态或低动态版本；关闭动效不减少必要信息。避免强频闪、持续屏幕抖动、正文色散和故意制造的操作延迟。

## 10. 三城的视觉递进

这部分对应完整产品规划，不表示 M2 已有三城。

第一城保留最多真实城市信息，异常主要集中在建筑局部；第二城让已发现的线路异常形成连续的空间扰动；第三城表现更大尺度的城市失常。公司的营业点在三种阶段中始终保留稳定、可辨认的标识。

视觉强度可以随城市阶段递增，但精确覆盖范围、危险路线和安全通道只能使用玩家已获知的信息。不能用美术提前标出未发现的真值。

## 11. 第一轮美术验证范围

先验证一套可比较的样板，再扩展全量资源：

1. 一张完整城市调度风格稿，包含已接管、未营业、正常营业、受影响四类状态。
2. 一间旅馆的正常与异常局部表现，保持同一构图。
3. 调查、点灯、模仿三张卡，同一版式。
4. 座钟与灯两个物品，各展示未封装、已封装、归库/安装状态。
5. 一个包含真实长文本的行动预览，用来检验可读性。

本次附带的总览样板用于确定气质、色彩和材质，不能替代上述状态稿、真实文字排版与交互验收。

验证时重点看：第一眼能否认出城市经营题材；能否分清“选中、占领、营业、队伍位置”；能否不依赖颜色读懂风险；连续阅读一段现场说明是否舒服；未知规则是否被美术泄露。

## 12. AI 美术素材的一致性约定

先固定同一套材质、视角、光线和色彩基准，再用通过讨论的样板作为后续参考。场景、物品、人物、背景、文字和功能图标分开产出与管理；正式文字由 UI 排版，功能图标保持规则化形状。

生成提示词保留核心短句：“现代城市异常回收公司；深空星图氛围；低饱和半写实；稀疏星尘；克制辉光；可信日常物品；清楚轮廓与大片暗色留白”。每项资产另外指定用途、视角、尺寸和必要状态。

本轮提案不冻结最终 logo、字体、具体人物面貌、完整特效和资产数量，也不直接替换现有游戏资源。下一次讨论优先校准：宇宙感与现实城市的比例、恐怖强度，以及信息面板的明暗。
