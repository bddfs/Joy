## 一个经营日如何推进

1. **准备：** 选节点，安排调查、回收或工程；配置队伍、工具、驻站与支援。只看档案、切换页面和修改未锁定计划不推进日期。
2. **锁定：** 一次校验全日安排并预付。人力、唯一工具、目标、通路、已知规程及支援固定下来。
3. **执行：** 指挥手操队；其他已委派事务等待统一日结。手操提前撤离不会让两名员工和该事务位重新可用。
4. **结算：** 处理归队、实际运输、归档、交付和工程，支付营业收入及必要支出，处理传播，然后判断交接或失败。

同日两支队伍使用锁定时已有的规程。手操队刚获得的知识可以用于本次现场，但要日终归档后，其他队伍下一日才能用于新委派。不能安排“上午抢修、下午借新路出勤”或“本日补充工具，本日另一队使用补入的次数”。

少排事务、完全委派或空计划都合法；空计划也会花掉一天并结算基本支出。达到交接条件后自动结束本城，没有无限刷营业收入的等待阶段。

来源：[经营日需求](https://github.com/bddfs/Joy/blob/693307638a7d9521b8ee185628d8d685b66e15b2/docs/requirements/Joy_需求规格说明书_v0.3.md#L158)、[计划校验](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L495)、[统一日结](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L305-L374)。

<a id="money"></a>
## 资金、零钱与收益

**公司资金**支付任务、工程及每日支出；**现场零钱**是尚未成功带回的收益，失败会丢失。成功撤离后按 1:1 转为公司资金。取得实物不会自动按其价值变现。

| 收益 | 到账条件 |
| --- | --- |
| 调查里程碑 | 成功取得指定记录，日终按地点合同付款；一次性 |
| 合同实物 | 必须封装、成功带回并实际交付；一次性 |
| 可选灯具出售 | 满足封装、归库及可用条件后登记出售，处置日结时到账 |
| 营业 | 按早晨有效网点与锁定驻站计算，每点每天一次 |
| 首次现场确认零钱 | 正确首次确认 +1；仍须成功撤离 |
| 紧急支援 | 压力模式的准备阶段界面可领取一次 +6，记录本次已使用；无压力默认局不显示此入口 |

旅馆无单独调查现金。医院调查为 2、回收为 5；源头调查为 2、回收为 8。详细收益见[合同表](contracts.md)。总部、交通枢纽没有合同目标，界面上的通用交付数字不能当成可领取任务。

计划中的“保守余额”只计算已知确定项：准备阶段从当前钱减尚未付的预付，加已锁定营业收入，减尚未付的日终费用。锁定后已扣预付不能再减。未完成合同、未撤出零钱与未知规则后果另列，不是保证收入。

到期必要费用付不出会经营失败，即使同日源头和网点目标都已满足。付完费用后余额刚好 0 合法。紧急支援当前记录使用状态，最终评价公式尚未实现；不要假设已经存在具体扣分。当前正常界面只在传播压力开启时显示支援按钮，不能把引擎里的通用方法当成默认无压力局可领取的收入。来源：[支援入口条件](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Scripts/Main.cs#L222-L225)。

来源：[资金需求](https://github.com/bddfs/Joy/blob/693307638a7d9521b8ee185628d8d685b66e15b2/docs/requirements/Joy_需求规格说明书_v0.3.md#L244)、[预算](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L16-L42)、[交付与唯一支付](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L718)、[紧急支援](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L376)。

<a id="operating"></a>
## 接管、驻站与有效营业

普通异常客户先完成所需合同实物和已确认归档规程，再支付 4 建设。公共协作点开局就能按公开条件施工，不需要先找异常物。总部和源头本身不算可建设的营业点；当前正常可经营的是旅馆、医院、公共协作点。

有效营业必须同时满足：设施已建成并到生效日、有驻站员工、维护正常、未被入侵、存在一条通往总部的可通行路径。

| 网点情况 | 当日收入 | 当晚封控 | 日终交接计数 |
| --- | --- | --- | --- |
| 早晨有效，日终仍有效 | 1 | 有资格 | 计入 |
| 早晨有效，当晚失效 | 仍领取晨间收入一次 | 按扩张前共同快照 | 最终失效则不计 |
| 旧点早晨失效，已留驻站，日内修复 | 不补发 | 修复后条件齐全可参与 | 扩张后仍有效则计入 |
| 本日刚建成 | 0 | 本日不参与 | 本日不计，次日起 |
| 无驻站、仍断联、被入侵或维护不正常 | 0 | 不参与 | 不计 |

每个有资格的网点每天封控一条相邻边，需要相应规程，或满足公共合作点的公开能力。所有预告箭头按同一时点判断，不因先结算某条箭头而改变其他封控；成功阻断不会改投另一个目标。

入侵、断路、设施和驻站是不同状态。修复通路不会删除异常规则；恢复旧设施不重新领取合同。源头交付取消其未落实的扩张，不撤销已经发生的运输后果。

来源：[节点与时序需求](https://github.com/bddfs/Joy/blob/693307638a7d9521b8ee185628d8d685b66e15b2/docs/requirements/Joy_需求规格说明书_v0.3.md#L172)、[有效营业检查](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L408)、[扩张快照](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L760-L785)。

## 现场状态速查

| 状态 | 初值 / 上限 | 用途与变化 |
| --- | --- | --- |
| 心志 | 12 / 12 | 归零立即出勤失败；后续治疗不能复活 |
| 护符 | 1 / 3 | 每枚抵挡一项允许抵挡的负面后果；不能支付成本或抵挡异动阈值、封门 |
| 行动 | 每轮 3 | 移动、出牌、搜查、封装等消耗；换轮重置 |
| 普通手牌 | 轮初 5 | 固定槽位，用牌留空至下一轮；抽弃细则见卡牌页 |
| 灯光 | 通常本轮有效 | 点灯使本轮照明，轮末结束；医院封装特别需要照明 |
| 异动 | 初始 0，下限 0 | 通常轮末 +1；当前 M2 达到 8 时立即损失 3 心志并将异动减 4，仍达 8 且存活则继续处理 |
| 背包 | 6 格 | 按实际物品占格；工具也有实体归属，不能凭空复制 |
| 墨水 | 初始 2 | 放置侧房消耗 1；首次进入新房间获得 1，重进不刷新 |
| 楼层轮限 | 12 轮 | 最后一轮到入口仍可先撤离；继续结束该轮会按封门判定 |

异常触发、敌影、异动袭击是不同来源。满心志并不等于没有触发异常，护符可能已经消耗。准确效果和结算例外见[异常百科](anomalies.md)。

## 观察、确认与规程

告示是场景中的信息；标明可靠的线索与实际日志属于可信证据。调查取得记录不等于自动确认答案。“看见物品”“发现可拾取物”“物品入包”“封装”“归库”“交付”也各有独立状态。

现场全队每轮最多一次候选提交，不额外耗行动。首次正确 +1 心志、+1 现场零钱；错误 +2 异动，立即检查是否达到袭击阈值。城市准备阶段每条规则每天一次，没有现场心志或零钱奖惩。错误候选跨模式保留；当天在城市判断过某条，该条当天不能再转现场提交。

已确认知识在本实例内保留。重新进房或出勤不会刷新领取过的实物或重复发奖励。三城及下一局知识成长属于完整规划，不能据此认为当前新建 M2 局会自动继承所有答案。

<a id="failure"></a>
## 撤离、失败与重新进入

存活队伍到入口可免费撤离，不需要先拿完合同或可选物。成功撤出后保留实际带回的合法实物、证据和零钱；未完成目标可以回访。

出勤失败时，当前 M2 的带入工具和本次拿到的实物都在现场按唯一位置遗落；已经花掉的工具次数不退，未撤出的零钱损失，证据归档保留。两名员工下一经营日恢复。可以安排空配装的手操队重返，拾取已发现的遗落工具，不能按旧版“失败自动返还带入工具”理解。

单次出勤失败不必然等于整局失败。但重返仍花当天事务和出勤费，且要在 5 日期限内完成公司目标。

## 保存与继续游戏

标题的“继续游戏”会显示已有进度与保存位置。M2 存档格式为 v2，使用独立档案；旧 v1 不自动迁移，不能只改文件名就当成新档。

完整保存点包括有效准备变更、锁定并开始现场、完整轮界、完整候选判断及奖励、出勤归队、日结与单城交接。**退出后恢复最近一次成功保存的完整检查点**，不总是无条件回到本轮开始：如果本轮确认奖励已经形成更晚的完整保存，就从那个位置继续。

抽牌进度、空卡槽、耗尽、库存、错误候选、工具次数和灯具额度共同保存。读档不提供免费补充、重抽或第二份物品。以界面显示的最近成功保存位置为准；保存失败不能视为已经存好。

实现记录说明：主档损坏时可尝试完整备份并提示，不支持的版本会拒绝加载而保留原档。这是当前存档方案，不是本次 Wiki 编写重新进行了损坏或断电测试。

## 术语对照

| 词语 | 意义 |
| --- | --- |
| 经营日 / 现场轮 | 城市排期单位 / 一次出勤内的战术时间，不能互换 |
| 事务位 / 员工 | 两项独立限制：有人不代表还有可排事务 |
| 实例 | 这一局某个具体物品、房间或规则；同名不等于同一个 |
| 库存 | 现场仍可取得的有限内容；重新进入不重生 |
| 参考牌 | 模仿当前采用的基础指令来源，不是复制上一笔奖励 |
| 耗尽 | 本次出勤不能再抽回使用，与普通弃牌不同 |
| 预留 | 本日唯一资源已被安排给特定任务，不能再分配 |
| 归档 | 本日证据成为公司下一日可用规程的时点 |
| 交接 | 当前城市目标完成后的结算；M2 到此结束 |
| 封装 / 封控 | 物品收容 / 城市边上的扩张阻断，互不替代 |
| 入侵 / 断联 | 节点被异常影响 / 与总部无通路，可能独立发生 |
| 已知后果 | 依据玩家当前公开信息可确定的部分，不能当作隐藏风险为零 |
