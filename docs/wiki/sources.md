## 本次原生界面核对

通过 computer-use 查看了用户已打开的原生客户端：标题及内置 M2 操作手册、继续游戏后的雾港第 1 日准备页面、城市节点网络和工具配装页面。页面显示 M2，六名员工、16 资金、七节点、初始十二张牌，以及隔离工具、源头专用箱和供应耗材；与本版内容清单相符。

此轮仅浏览既有进度与说明，未锁定经营日、未出勤、未重开局或修改配装。没有取得客户端的不可变构建哈希，因此只能说所见页面与该开发提交的 M2 内容相符，不能证明运行包逐字节等同于该提交。

异常真值、触发边界、所有物品状态和各条日程主要依据固定版本文档与代码核对，并非本次逐个手玩得出。实施记录中“23 条日程”“784 项断言”等属于开发者记录，本次未重新运行。旧轮次的种子 413 单城试玩也不替代本次 M2 全量验收。

## 容易混淆的版本差异

| 条目 | 设计 / 旧文档 | 当前 M2 或最新修订 | Wiki 处理 |
| --- | --- | --- | --- |
| 灯具名字 | 不灭床头灯 | 实物名“侧房灯” | 作为同一 M2 设计对象的别名，不计两件 |
| 旅馆座钟名字 | 旧版停摆座钟 | 镜中住客的座钟 | 区分历史名称与当前实例 |
| B 路线余额 | 旧策划最终 24 / 20，安装 18 | 最新需求与实施记录为 22 / 18，安装 16 | 采用最新校正账例 |
| 轮中退出 | 旧策划简写回轮初 | 回最近成功完整检查点；可能晚于轮初 | 采用 FR-SAVE-06 与 M2 v2 说明 |
| 敲门 | 基础牌，可模仿 | M2 无允许应答房门 | 保留条目，明确没有当前合法目标 |
| 卡组调整 | 完整工具站有费用和次数 | M2 准备模板可免费调整，付费升级未完成 | 分开描述，不给玩家虚构升级入口 |
| 稀有直接揭晓 | 完整设计允许专家批注等来源 | 透镜只在 Legacy 投放，M2 无相应来源 | 标为历史或规划，不写成 M2 必得物品 |
| 入侵预告的断路文案 | 压力预告写入侵并断相邻路 | 当前 M2 目标是医院；代码只对交通枢纽执行断边 | 标为文案 / 执行差异，不把断路写成 M2 必然结果 |
| 研究 | 规划有横向研究成长 | 当前研究接口仅消费实物记记录；普通 M2 没有可用完整研究入口与能力链 | 不作为灯具的已开放收益路线 |
| 总部交付数字 | 通用 UI 可显示“实物交付 +5” | 总部没有合同目标，不能按该数字领取 | 不增造总部回收合同 |
| 南线运输守则 | Legacy 有明确线路实例 | M2 边没有绑定这条规则，开压力也不添加 | 历史栏目单列 |
| 异动阈值 | 策划明确回落到 4；需求简写“回落 4” | M2 每次袭击后减 4，7 + 2 会结算到 5 | 并列说明，按当前效果预判，不掩盖设计差异 |
| 紧急支援 | 设计为准备阶段的一次性缓冲 | 当前正常按钮仅在压力模式开放 | 不计入默认无压力路线的可用收入 |

压力差异来源：[预告生成](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L788)、[实际扩张](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/CityEngine.cs#L760-L785)；异动与支援来源：[阈值循环](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Core/FieldEngine.cs#L559-L567)、[支援入口](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/Scripts/Main.cs#L222-L225)。其余细项引用见对应百科页。这里记录可查证的不同，不代表本次改动了客户端或设计文件。

## 完整版本规划目录

以下为未来规划，不应在当前 M2 中寻找对应关卡或奖励。

| 内容方向 | 已明确的部分 | 仍未形成的百科数据 |
| --- | --- | --- |
| 第一城 | 地点异常为主，约 6–7 节点，暂定 5 日、2 营业点 | 完整随机地点与合同池 |
| 第二城 | 线路大异常覆盖多个地点，约 8–9 节点，暂定 6 日、3 营业点 | 城市名称、所有线路规则与节点条目 |
| 第三城 | 全城规则影响运输或经营，约 9–10 节点，暂定 7 日、3 营业点 | 城市名称、全城规则和源头变体全集 |
| 连续三城生成 | 管理与混合两类路线均需按实际资产连续完成；不能每城重置满资源 | 生成算法、后备池与完整验证结果 |
| 网点专业 | 调查、工具维护、接应运输、回收仓储；每点一类，每出勤至多一份支援 | 全部升级名称、价格、效果与兼容表 |
| 更多卡牌与组合 | 约 24 种牌的预算，普通工具、升级与异常装备承载成长 | 尚未冻结的新增候选牌与强化清单，不能由 Wiki 命名补齐 |
| 更多规则、物品、委托 | 约 18 条规则、12 件异常物、12 委托模板的预算 | 完整名称、触发、获取方式和数值池 |
| 稀有揭晓 | 一次只揭晓合法目标的一条规则，实例记录唯一 | 专家批注的载体、频率与正式获取途径 |
| 跨城协作 | 前两城各选一项，远征至多两项；旧城不无限送钱 | 协作技能清单和费用 |
| 跨局成长 | 保留知识、工具解锁、研究、分公司成就；新局重新经营 | 解锁清单、支援预算单位、成就与评价公式 |
| 发行范围 | 单人，Steam，Windows/macOS，Godot .NET + C# | 正式包、Mac 验证、硬件规格、手柄和语言范围 |

时长目标仍为完整三城约 2–3 小时，固定 M2 单城不应据此延长到同样时长。来源：[完整方向与成长需求](https://github.com/bddfs/Joy/blob/693307638a7d9521b8ee185628d8d685b66e15b2/docs/requirements/Joy_需求规格说明书_v0.3.md#L94)、[最新策划](https://github.com/bddfs/Joy/blob/693307638a7d9521b8ee185628d8d685b66e15b2/docs/design/异常回收公司详细策划案_v0.2.md)、[实施记录未完成项](https://github.com/bddfs/Joy/blob/9cbe156779aa38dbce0b798b5db0143df5282846/docs/implementation-m2.md#L94)。

## 后续怎样更新百科

每次内容更新先记录文档修订和开发提交，再核对世界工厂的实际投放与界面入口。新增条目应填写名称、状态、出现条件、效果、消耗、计数周期、获取或处置方式、相关条目与来源；同一个实物更名保留别名，不重复计数。

数值或时序修改时，同步更新相关合同、物品和路线账表。历史条目保留原版本标签；未经投放或验证的能力不能靠删掉“规划”字样变成已上线内容。
