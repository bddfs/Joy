### 0.3 修订范围与已确认决定

本版基于提交 `834033f3ed2e01b63b5b2d8926f2e0763e732856` 的需求 v0.2，落实 S06 的三项确认。v0.2 保留供版本对照，当前评审以 v0.3 为准；本次没有新增 Demo 试玩、玩法实现或已通过的验收结果。

- 运输仅预览玩家已知的后果。未知规则只依据已有线索提示不确定性，不通过节点高亮、精确损失或按钮状态泄露答案；允许在满足物理与任务条件时承担未知风险。
- 疾走不覆盖模仿参考，也不成为可模仿指令。“安全房搜查 → 疾走到另一房间 → 模仿搜查”可以成立，仍按当前位置、真实库存、行动成本和结果事件结算。
- 地图生成必须保证三城存在连续可完成的合法路线。跨城按该路线实际交接的资金、工具、员工及其状态继续推演，不能以各城单独可完成代替完整远征验证。

对应需求为 FR-SPR-05、FR-UI-07、FR-MIM-01、FR-MAP-06；验收补齐 AC-06、08、15、26、30、33。已确认的目标与尚待设计的算法、重试预算和内容参数分别记录。

## 02 产品目标、范围与非目标

### 产品要求

**PR-01 公司经营与现场玩法形成一个循环。** 玩家是连锁异常调查回收公司的老板；城市层管理资金、节点、岗位和派遣，现场层通过证据、卡牌与路线完成调查、回收和撤离。成果必须能转化为合同、接管或后续作业能力。来源：S01 §01-03，p3。

**PR-02 完整远征包含三座随机城市。** 从地点异常递进到线路异常和全城守则；城市可以回访节点、重新选路。完整一局以约 2 至 3 小时为体验目标，支持分多次游玩；实际时长待验证。来源：S01 §01、04、18，p3-4、14；暂定时长见 P-TIME。

**PR-03 面向 Steam 的单人桌面游戏。** 计划支持 Windows 和 macOS，采用 Godot .NET + C#；二维、鼠标操作和文字信息丰富的界面是当前产品方向。最低系统、硬件和分辨率尚待决定。来源：S01 §02，p3；S02 用户补充。

**PR-04 规则应能被观察和推理。** 恐怖感来自异常条件与可理解后果；可靠信息必须可信，高危险后果应提供先兆和应对窗口。不得把突发即死作为常规难度来源。来源：S01 §02、11、15，p3、9、12。

### 验证范围与完整范围

最小验证版是完整设计获准后的验证范围，不代表本文件授权立即编写玩法。它必须验证经营与多队调度，不能只交付旅馆单关。

| 维度 | 最小验证版 M | 三城完整目标 F |
| --- | --- | --- |
| 地图 | 1 城，6 至 7 节点，局部规则加一条测试线路规则 | 3 城及地点、线路、全城范围递进 |
| 派遣 | 2 队、2 事务位、基础驻站 | 最多 3 队、3 事务位 |
| 闭环 | 普通出勤、保守调查、标准回收、常规维护、工程、源头处置 | 完整业务、专业方向及跨城协作 |
| 经营 | 接管、驻站、连通、一次恢复 | 专业分站与更多网络抉择 |
| 场所 | 旅馆与轻量医院 | 旅馆、医院、地铁三类核心现场 |
| 内容预算 | 10 种基础牌；6 至 9 条规则；4 至 6 件异常物 | 约 24 种牌、18 条规则、12 件物品、12 个委托模板 |
| 一致性 | 资源互斥、唯一库存、统一日结、可解释规则和读档一致性必须验证 | 同一约束扩展到三城与长期成长 |

### 首版非目标

- 骰子借贷、自走棋、时间残影、自由建筑装修、复杂员工关系和实时多人联机。
- 员工情绪、饮食、忠诚、社交、逐人技能树；税、利息、多货币市场和薪资谈判。
- 每段地铁都制作战斗、每次经过旧网点都强制重玩完整关卡。

来源：S01 §02、06、10、12，p3、5、8、10。大量立绘、过场和复杂动态场景属于后续决定，不是当前必要范围。Steam 成就、云存档、创意工坊、手柄、Steam Deck、多语言和 DLC 清单均未被定义，不能自动纳入首发承诺。

## 03 术语与必须保持的约束

| 术语 | 定义 |
| --- | --- |
| 远征 / 城市 / 出勤 | 完整三城局 / 一个经营阶段 / 一次现场或委派任务 |
| 经营日 / 事务位 | 城市推进单位 / 当日出勤或工程的安排上限 |
| 服务点 / 专业分站 | 接管后建立的基础设施 / 在基础设施上选择的专业用途 |
| 有效营业 | 需要满足连通、驻站、维护等条件；收入、封控、交接的取样时点不同 |
| 规则实例 / 异常家族 | 当前地点、线路或城市的具体守则 / 跨局可保留的知识类别 |
| 基础指令 / 行为标签 / 结果事件 | 实际执行动作 / 动作身份 / 动作引发的库存、携带、灯光等变化 |
| 源头扩张 / 运输入侵 | 敌方预告传播 / 玩家携带或运输违反规则产生的后果 |
| 唯一实例 | 具有独立身份的物品、稀有工具或合同目标，不能因界面或结算复制 |

以下约束适用于所有模块：同一员工不能重复占用；同一实物只有一个位置和持有者；合同奖励与营业收入不能重复结算；已锁定任务不消费同日尚未归档的新情报；敌方扩张采用共同快照；存档保留已付款、已领取、资源预留与随机进度。需求的任何实现方案都不得破坏这些约束。

## 04 城市经营与派遣需求

### 4.1 经营日

**FR-DAY-01 四阶段。** 经营日依次为准备、锁定、执行、结算。查看信息和调整未提交方案不推进时间。来源：S01 §05，p4。

**FR-DAY-02 事务上限与可选手操。** 完整版按当日事务上限安排出勤或工程，每日最多一项手操，其余可委派或建设；驻站不占事务位但占员工。允许少排或全部委派，空闲不额外获利也不暂停期限。来源：S01 §05，p4-5；参数 P-STAFF。

**FR-DAY-03 提交校验与预付。** 锁定前校验员工、资金、通路、工具次数和唯一目标；锁定时预付出勤、工程费用，固定岗位、资源和受理条件。冲突必须指出对应对象。来源：S01 §05、07、21，p4、6、16。

**FR-DAY-04 锁定后不可重排。** 手操主动撤离或提前结束不能回到晨间重配已派出的队伍。依赖本日未完成回收或工程的另一任务安排到次日，不通过任务排序取得同日隐含收益。来源：S01 §05、07，p4、6。

**FR-DAY-05 信息归档边界。** 手操新情报可即时用于本次现场并记录日志；日终归档后，才成为其他队伍下一经营日可使用的公司证据。已锁定委派仍使用提交时条件。来源：S01 §05、25，p4、18。

**FR-DAY-06 唯一日终流程。** 归队与交付 → 合同和工程 → 当日营业收入与维护 → 异常扩张 → 城市交接或失败 → 下一日预告。多队任务只推进一次经营日。资金不足与交接同时发生的细节见 D-03。来源：S01 §05，p4-5。

**FR-DAY-07 新建与旧点修复分开取样。** 收入依据晨间有效运营和锁定岗位；新建节点次日起营业和封控，旧点当日修复不得追领收入。旧点若晨间已留驻站，且当日工程恢复连接及维护，可参加当晚封控。来源：S01 §05、09，p4-5、8。

**FR-DAY-08 交接在扩张之后。** 最后一天日终满足目标仍算成功；满足交接后不开放无限等收入阶段。末日入侵或断联点不计入有效营业点。修复与新建对交接资格的完整矩阵见 D-01。来源：S01 §05、12、18，p5、10、14。

### 4.2 员工与队伍

**FR-STAFF-01 简单编制。** 员工记录待命、驻站、出勤、施工、恢复五种工作状态；恢复员工不提供当日能力，恢复结束回待命。来源：S01 §06，p5。

**FR-STAFF-02 人员互斥。** 同一员工不能同时出勤、驻站和施工；出勤、驻站、工程、研究按各自人力需求占用。不同模式使用同一个人力池。来源：S01 §05-06，p4-5；参数 P-STAFF。

**FR-STAFF-03 队伍配置。** 队伍差异主要来自卡组、装备和规程。普通基础配置可复用模板，稀有强化与异常装备按真实实例分配。来源：S01 §06、14，p5、11-12。

**FR-STAFF-04 扩编与恢复。** 扩编占工程事务、支付成本并增加后续经营支出；失败员工当前默认恢复一经营日，无永久死亡。扩编次数和恢复处罚均为暂定方案，需验证后冻结。来源：S01 §06、13、26，p5、11、18；参数 P-STAFF、P-FAIL。

### 4.3 手操、委派与规程

**FR-DSP-01 共用业务和库存。** 手操与委派共用地点、合同目标、库存、接管和完成记录，不能用不同模式重复取得同一目标。来源：S01 §07，p5-6。

**FR-DSP-02 模式门槛。** 手操要求可达与基础配置；保守调查要求可达观察点，产出一条未获可靠线索或指定记录；标准回收要求必需规则、工具、收容和运输条件齐全；维护要求已建立规程且目标未完成。来源：S01 §07，p6。

**FR-DSP-03 委派预览。** 提交前展示固定费用、工具及次数、确定成果、不确定部分和撤退条件。首版依据已知门槛与明确成本受理，不用隐藏成功率造成突发团灭；不足时可转保守调查。来源：S01 §07，p6。

**FR-DSP-04 关键回收可委派。** 取得证据并确认规程、满足收容和运输条件后，源头等关键回收也可委派。管理路线仍要作出证据判断，不能无条件自动通关。来源：S01 §07-08，p6-7。

**FR-DSP-05 完整消耗校验。** 规程检查能力、剩余次数、耗尽、封装和运输；一次模仿不能支持两个豁免步骤，一次性工具真实消耗。稀有实例和唯一目标在锁定时预留，禁止重复分配。来源：S01 §07、14，p6、12。

**FR-DSP-06 城市确认。** 准备阶段根据已归档证据，每条规则每经营日提交一次候选判断。正确记录规程，不发现场心志或零钱；错误候选保留且本日不能再次提交该条。与现场共享确认和领奖记录，证据不足不能确认。来源：S01 §07、15，p6、12；配额衔接见 D-04。

### 4.4 地图与生成

**FR-MAP-01 可回访网络。** 地点为大节点、枢纽为小节点，连线支持双向调动、分叉、汇合和环路。已侦察连接不因改选分支消失；经营距离按路径计算。来源：S01 §08，p6-7。

**FR-MAP-02 骨架与内容抽取。** 城市倾向影响地点、合同和异常权重，不保证固定最优路线；同类地点可重复，部分类型可缺席。节点数量包括总部和源头。来源：S01 §08，p6-7。

**FR-MAP-03 信息分层。** 初始展示登记地点和主要连接；未知节点隐藏身份、内部结构或异常细节，而非任意删除已有路径。来源：S01 §08，p7。

**FR-MAP-04 单项可行性。** 检查总部附近至少两个可承担任务、合同与实际地点匹配、证据和必需工具可达、关键通道无自锁，以及基本配置可完成必要调查和撤离。分城结构基线为：第一城两个起步方向和一条环路，第二城至少一个多线枢纽，第三城两种源头接近或恢复办法。来源：S01 §08，p7；数量仍受暂定参数声明约束。

**FR-MAP-05 全城可完成性。** 同时验证混合手操与管理路线存在合法日程，将证据次日归档、建造次日起效、人员、工具、资金、通路和期限全部计入；不能用“单任务可达”代替全局证明。检查不通过的地图如何重试或回退见 D-08。来源：S01 §08、25，p7、18。

**FR-MAP-06 三城连续可完成〔用户补充〕。** 完整远征的生成结果必须分别存在一条管理路线和一条混合手操路线，能够在各城期限内连续完成三城；两条路线可以采用不同决策。每条路线从同一个合法开局状态出发，逐城传递实际资金、工具实例与剩余次数、实物、员工编制与恢复状态、维护支出及已用支援，按真实补充、消耗和归档时点继续推演；不得每城重置为初始资金、默认工具或全员可用，也不能借用另一条路线的资产来判定通过。检查计入对应模式的事务位、人力互斥、关键物与证据、建设生效、营业与交接条件。按城生成时，必须以玩家进入下一城的真实交接状态验证后续连续可完成性；预先生成时，须检查完整三城日程及中间交接状态，不能以三个独立单城样例拼接替代。失败的生成候选按 D-08 重试或回退，不暗中修改已生成地图、已确认规则或赠送未声明资源。保证至少存在合法完成路线，不保证任意决策都能获胜；经营日内的资源浪费、期限耗尽等仍按既有失败规则处理。算法、验证集合和重试预算仍属 D-08，三城连续可完成的目标本身已确定。来源：S06；FR-MAP-05、FR-META-01/02/03、P-STAFF。验收：AC-08、AC-33。

### 4.5 接管、营业与交通

**FR-NODE-01 明示接管资格。** 合同公布所需结论、关键物和启动投入；到达或一次普通搜索不自动取得资格。非异常合作点可用公开签约或运输条件代替现场回收。来源：S01 §09，p8。

**FR-NODE-02 多维状态。** 建设状态至少区分未接管、可接管、已建成；异常状态区分可按规程管理与受入侵。设施存在、连通、驻站和维护条件分别记录，不将断联等同于未接管。来源：S01 §09-10，p8。

**FR-NODE-03 营业资格。** 服务点须通过可通行路线连接总部、有驻站人员并满足维护条件。断联暂停依赖总部的营业、跨区支援和持续封控，设施与知识保留。来源：S01 §10，p8。

**FR-NODE-04 基础点与专业用途。** 基础服务点即可营业、封控；当前专业方向为调查、工具维护、接应运输、回收仓储，每点选一类，每次出勤最多一份有效网点支援。具体升级成本和效果待定。来源：S01 §09、26，p8、18；暂定方案见 D-09。

**FR-NODE-05 回访与恢复。** 已接管点默认进入服务界面，保留发现、库存、合同与规程；只有新增目标、入侵或异常部分开启新任务。清除已知入侵、恢复连通与驻站不重新支付基础建设费。来源：S01 §09、11，p8-9。

**FR-NODE-06 通行与异常独立。** 恢复列车不自动解除线路规则，封控不豁免现场或全城守则；可通过环路、抢修或任务允许的步行应对断联。步行附加费、初始异动等在出发前公布。来源：S01 §10，p8。

### 4.6 扩张与运输

**FR-SPR-01 可追踪预告。** 每个扩张记录活跃来源、目标边/节点和后果，准备时显示当晚箭头。锁定后不得临时改目标；可阻止箭头仍显示阻止条件。来源：S01 §11，p9。

**FR-SPR-02 封控范围。** 有效服务点依已掌握规程选择相邻边封控；未知传播类型只得到预告说明的有限效果。每点当日封控数量按参数设置。来源：S01 §10，p8；参数 P-NODE。

**FR-SPR-03 共同快照与同时落实。** 完成任务、工程与玩家运输入侵登记后，计算当晚可用封控；所有敌方箭头用同一快照判断，再同时落实未被阻止的箭头。执行顺序不得改变结果。来源：S01 §05，p5。

**FR-SPR-04 一跳与源头生命周期。** 当晚只执行已预告的一跳，新侵入地点不当晚连锁传播。回收源头不再生成，其尚未执行箭头取消；封控成功不改投其他目标。新入侵须追溯其他活跃来源。来源：S01 §05、11，p4-5、9。

**FR-SPR-05 玩家运输另行登记〔基线及用户补充〕。** 运输确认前仅预览玩家已知的后果及受影响节点，说明依据的已知条件；尚未知晓的运输规则只依据已有线索显示不确定性，不通过高亮、精确节点或损失、按钮状态及提示差异泄露答案，也不把暂无已知后果标为安全。运输不额外要求所有未知规则先被确认；满足已公布的物理与任务条件时，玩家可以选择承担未知风险。手操与委派仍分别遵守既有受理门槛，不因此放宽标准回收要求。改变携带物、封装或路线可避免相应已知后果；实际运输仍按全部适用规则结算，并以真实日志记录结果。归队时登记入侵，早于当晚封控快照，影响次日营业；随后交付源头不撤销已有运输入侵。来源：S01 §18，p14；S06；FR-DSP-02、FR-UI-05/07。验收：AC-06、AC-26。

**FR-SPR-06 三城规则递进。** 按地点、线路、全城扩大影响范围，从相容池抽取规则；不能临时针对当前牌组生成克制组合。城市名称及示例红箱/封装规则可替换。来源：S01 §11、18，p9、14。

### 4.7 合同与经济

**FR-ECO-01 真实到账。** 现场零钱成功撤出后转入公司资金；合同按调查里程碑或实物交付条件付款，未撤出物品不可提前折现。调查、指定回收、维护、线路恢复、源头处置各有明确业务目标。来源：S01 §03、12-13，p3、9-11。

**FR-ECO-02 支付唯一性。** 已完成合同、调查里程碑、领取点和房间库存不得因回访或切换模式重置；营业收入每天只结算一次，安全任务目标也有限。来源：S01 §12、25，p10、18。

**FR-ECO-03 可解释账目。** 区分预付、合同、营业、基本支出及明确标注的特殊维护。基本支出已覆盖常规驻站，不再逐人重复扣工资。准备阶段显示预计余额和最坏结果下缺口。来源：S01 §05、12、21，p4、9-10、16。

**FR-ECO-04 经营失败。** 必要经营支出无法支付时进入明确失败结算。必要支出清单、临界余额和同日成功/失败优先级需 D-03 冻结后才能实现完整判定。来源：S01 §12、20，p10、15。

**FR-ECO-05 紧急支援为暂定。** 当前默认每远征一次准备阶段支援，获得资金并降低评价；是否保留、金额与评价影响待验证，不能预设为每局必选。来源：S01 §12、26，p10、18；P-FAIL。

## 05 现场、卡牌与规则需求

### 5.1 出勤与撤离

**FR-FLD-01 出发信息。** 出发前公布层数、深入门槛、固定费用、已知风险和失败损失规则；普通、关键、源头任务采用不同深度预算，不把完整三层旅馆套给所有节点。来源：S01 §04、13，p4、10-11。

**FR-FLD-02 回合资源。** 现场按行动点、手牌、心志、护符、灯光、异动及楼层轮限推进；轮末弃手牌、灯灭并按流程结算，牌库不足重洗弃牌。具体初值见 P-FIELD。来源：S01 §13，p10。

**FR-FLD-03 基础操作可用。** 移动、徒手搜查、拾取已发现遗落物和满足条件的基础封装不依赖特定卡；查看地图、日志、物品和已知规则免费。无效目标在扣费前给出原因。来源：S01 §13、17，p10、13。

**FR-FLD-04 旅馆空间规则。** 旅馆可放置房间，消耗行动与墨水，首次进入新房间获得墨水；医院、地铁复用公共行动与规则，但不要求相同房间拼接玩法。具体初值见 P-FIELD。来源：S01 §13，p10。

**FR-FLD-05 主动撤离。** 入口是基础出口，存活队伍返回即可免费撤离，无须集齐深层封印；接应可提供满足已公布条件的备用出口。最后一轮到入口可以先撤离，继续结束该轮则正常判定封门。来源：S01 §13、15，p10、12。

**FR-FLD-06 部分成果可保留。** 成功撤离将背包实物和零钱归入本城资产，并完成已满足的调查里程碑；拿到物品不等于交付。未完成目标保留供回访。来源：S01 §13，p11。

**FR-FLD-07 失败与重返。** 保留已记录证据和公司资产；必需合同物、封印在地点遗落并保留唯一记录。重返不重发发现、调查或交付奖励，既有房间与确认规程保留；现场临时资源按新出勤配置重置。带入装备和普通战利品损失见 D-02。来源：S01 §13，p11。

**FR-FLD-08 护符边界。** 标记为可抵挡的负面现场规则或普通敌影攻击逐项消耗护符并取消对应后果。护符不能抵扣成本、异动阈值袭击、城市扩张或封门失败。来源：S01 §13-15，p10-12。

**FR-FLD-09 敌影可应对。** 普通敌影公开意图和作用区，出现当轮先预告，最早下一轮末执行。仅明确可驱离的敌影可被驱离，守则诅咒不自动归类为敌影。活跃数量暂见 P-FIELD。来源：S01 §14，p12。

### 5.2 卡牌与工具

**FR-CARD-01 出勤前构筑。** 公司界面调整队伍牌组，普通工具可以配发，稀有强化按实例分配；起始牌组、上下限和基础牌效果见 P-CARD。来源：S01 §14，p11。

**FR-CARD-02 获得与借用。** 新工具提供候选并允许拒绝；现场找到的牌可免费进入手牌，但出牌照常付费，奖励点只能领取一次。借用牌仅本次出勤有效，其余进入公司工具库后再选择装入。来源：S01 §14，p11。

**FR-CARD-03 调整服务。** 工具站提供替换、删牌或升级；删除不得低于牌组下限，费用和每日服务次数暂见 P-CARD。升级应明确改变的用途和条件，不能默认所有效果一起提高。来源：S01 §14，p11。

**FR-CARD-04 委派不虚构操作。** 委派使用同一任务要求、工具标签和稀有实例，不假装打出未选牌或获取隐藏组合收益。来源：S01 §14，p12。

**FR-CARD-05 逐格与用途约束〔基线及用户补充〕。** 疾走沿合法通路逐格结算，不覆盖模仿参考，也不成为可模仿指令；不豁免途中规则与成本。卡牌的数据须包含基础指令、行为标签、模仿白名单资格、用途限制及借用状态。疾走与模仿的关系按 FR-MIM-01 执行；其他用途枚举和新增牌的边界见 D-06、D-09。来源：S01 §14、25，p11、18；S06。

**FR-CARD-06 可感知的组合成长〔本次吸收〕。** 内容设计至少提供两套能改变行动顺序、资源取舍或合法工具配置的可行组合，并在首次触发时明确列出基础效果、组合来源、附加变化和消耗。单纯把所有数值一起增大不足以证明构筑差异。按用户确认，成长由现有工具升级与异常装备承载，不增加独立遗物系统。具体内容、强度与获得途径按 D-09 评审，不直接移植 Demo 的钢笔、调查数值或房后固定掉落。组合不得越过真实库存、背包、剩余可靠线索、收容或合同交付条件。来源：S01 §14、17，p11、13-14；S04、S05。验收：AC-29、AC-20。

**FR-CARD-07 组合效果的身份与次数〔本次吸收〕。** 每项升级或装备效果明确作用对象、触发事件、有效时点、叠加方式、计数周期和普通 / 模仿是否共享。涉及现有“每房”次数时按地点中的房间实例记录，离开重进不恢复；出勤或远征周期明确另记。移交装备、读档、换队或切换委派不重置尚未到期的实例额度；不同队伍不能同时使用同一稀有实物。委派仅使用规程中明示可受理的组合能力。具体效果清单中未写清这些字段的内容不得进入冻结范围。来源：FR-STAFF-03、FR-DSP-05、FR-RULE-02、FR-ITEM-01；S04、S05。验收：AC-29、AC-09、AC-18。

### 5.3 守则、证据与结算

**FR-RULE-01 显式规则身份。** 每条规则记录实例范围、触发事件、时点、后果、可靠线索和豁免条件。地点甲的结论不自动用于地点乙，家族知识只能缩小判断范围。来源：S01 §15、25，p12、18。

**FR-RULE-02 显式计数周期。** 按回合、出勤、地点实例分别累计和重置；实例库存、唯一领取与合同支付不能随换轮或重返刷新。卡面或规程必须说明周期。来源：S01 §15，p12。

**FR-RULE-03 证据可信层级。** 区分原始告示、可靠线索、行动观察和玩家假说；告示可不可靠，基础卡面、实际日志和标为可靠的线索不得说谎。取得相关线索或观察触发后才开放候选验证；稀有来源的直接揭晓是 FR-RULE-09 规定的显式例外，不据此改变普通调查牌。来源：S01 §15，p12；S05 用户补充。

**FR-RULE-04 假说确认与奖励。** 保留错误候选记录，不允许反复提交同一错误答案刷反馈；正确结论只奖励一次，城市与现场共享确认。候选数、正确/错误效果暂见 P-RULE；现场配额范围待 D-04。来源：S01 §07、15，p6、12。

**FR-RULE-05 唯一行动流水。** 检查目标和成本 → 支付并记录行动前状态 → 基础指令、移动及库存变化 → 实际行为和结果事件 → 全城、线路、地方规则 → 护符和后果 → 任务、日志、终局。任何阶段心志归零立即失败，后续正面效果不得补救。来源：S01 §15，p12。

**FR-RULE-06 触发边界。** 每规则每行动最多触发一次；规则追加奖惩默认不递归触发新一轮守则，显式连锁须定义次数上限。依行动前条件的规则用前快照，依取得物品的规则用取得后状态。来源：S01 §15，p12。

**FR-RULE-07 轮末与即时异动。** 每次异动增加达阈值后立即执行袭击并回落，轮末增长同样处理。轮末按敌影 → 灯光结束 → 异动增长与阈值袭击 → 封门期限结算；其中心志归零即失败。来源：S01 §15，p12；P-FIELD。

**FR-RULE-08 可理解的叠加规模。** 活跃主守则按预算限制，线路/全城规则替换部分地方名额；物品条件明示，未封装且主动外溢的携带物按预算限制。相容性规则表和完整内容池仍需设计。来源：S01 §11、15，p9、12；P-RULE、D-06。

**FR-RULE-09 实践为主、稀有揭晓为例外〔用户补充〕。** 普通调查获得当前允许取得的可靠线索，行动实践留下可信观察；玩家据此提出和验证候选，普通调查不默认直接给出完整守则答案。允许比较稀有的卡牌、道具或特殊事件奖励揭晓一条尚未确认的合法规则实例；每项来源明确可选目标范围、选择或随机方式、使用条件、消耗及次数，不能默认为全地图或全部守则。揭晓后将目标实例的完整答案可靠地写入已知规则与确认记录，注明特殊来源，并更新该实例预览；普通观察、错误候选和既有证据仍保留。与现场 / 城市的既有确认共享唯一台账，不能额外再领一份相同确认奖励；首次确认奖励是否随特殊来源发放按 D-09 的内容条目明确。纯揭晓来源没有合法未确认目标时，在扣费前说明，不扣费、不消耗机会；兼有其他效果的复合卡或事件按冻结内容条目明确可用性、独立成本和无目标行为，并在提交前展示，不能暗中收费。揭晓不豁免物理、封装、库存、工具或运输要求，不自动完成实物合同，也不授予其他地点新实例或下一局的答案。验证范围至少包含一个稀有揭晓样例，不要求卡、道具、事件三种载体全部制作；稀有程度和内容预算待 D-09 确定。来源：S05 用户明确补充；FR-RULE-01/03/04、FR-DSP-06、FR-META-05。验收：AC-32、AC-10、AC-20。

### 5.4 模仿

**FR-MIM-01 参考与可用性〔基线及用户补充〕。** 模仿参考最近一张会更新参考的行动牌，只允许白名单指令。模仿自身、查看、基础移动、疾走与换轮均不覆盖参考；疾走本身不属于模仿白名单，进入新楼层仍重置参考。其他非模仿行动牌沿用更新参考的规则，若其指令不在白名单中，模仿显示不可用，不能自动回找更早的合资格牌。已有搜查参考时可先疾走再在当前位置模仿搜查；没有参考时打出疾走不会产生参考。今后新增移动牌须在内容条目中明确是否更新参考，不把疾走的例外自动扩展为所有移动牌。来源：S01 §16，p13；S06；D-05 已确认。

**FR-MIM-02 执行当前指令。** 模仿在当前位置执行基础指令并扣除真实库存，不复制旧房间物品、已经算出的最终数字、规则追加收益、抽牌、行动点、移动或再次模仿。来源：S01 §16，p13。

**FR-MIM-03 标签与结果分离。** 不产生原牌的搜查、敲门等行为标签，但仍产生获得、携带、灯光、恢复等实际结果事件；容量、物理条件、封装和运输限制仍生效。来源：S01 §16，p13。

**FR-MIM-04 共享额度与暂定稀缺性。** 普通与模仿休息共用房间额度，搜查共用库存，护身共用上限；模仿不创建第二套次数。用户已选定每次出勤耗尽作为先行平衡验证方案：成功打出后本次出勤不再重洗回牌库，无效操作不消耗该牌；牌的可用资格按出勤周期恢复。行动成本继续按 P-CARD / 基础牌表，不叠加新版每房一次或额外损失 1 心志。稀有实例预留和共享能力次数继续按 FR-DSP-05 校验；多张副本的组牌上限属于 D-09 内容约束，不能默认复制稀有牌绕过额度。旧版重洗和新版每房一次均不能证明此方案已验证。来源：S01 §16、26，p13、18；S05 用户确认；P-MIM、D-07。

## 06 实物、交接与长期成长需求

### 6.1 唯一实物

**FR-ITEM-01 归属与处置权。** 物品具有唯一编号、位置、持有者、占格、收容、合同归属和用途；地点、背包、仓库、装备、研究、安装之间真实转移。同一物品不能同时出售、研究、装备；指定归还物按交付处理。来源：S01 §17、25，p13-14、18。

**FR-ITEM-02 入包决策。** 入包前展示体积、已知价值和明确携带后果；容量不足允许放弃或将已有物品放回当前房间。放下不刷新库存或奖励次数。来源：S01 §17，p13。

**FR-ITEM-03 发现与领取分开记录。** 搜查包含当次合法领取；拒绝入包不触发获得/携带，物品留在已发现位置。之后拾取只移动已有实物，搜查额度耗尽也不删除遗落物。来源：S01 §17，p13。

**FR-ITEM-04 封装不抹去身份。** 先满足物品收容条件，再用基础操作或牌封装；只停止明确注明的外溢，不自动删除颜色、重量、身份或城市标签。来源：S01 §17-18，p13-14。

**FR-ITEM-05 研究与长期解锁。** 有处置权的物品可按用途研究，消耗应真实生效；保留研究和图鉴成果，不将本局实物库存带入下一局。具体物品效果属于候选内容，冻结清单见 D-09。来源：S01 §17、20，p14-15。

### 6.2 城市交接与远征结果

**FR-META-01 双重交接目标。** 源头回收完成且满足规定的有效营业点条件，才可交接；城市开局公布必需条件，允许客户组合选择，不要求占满地图或用完期限。来源：S01 §04、18，p4、14；P-CITY。

**FR-META-02 总部资产转移。** 交接前显示资金、工具、员工、研究和留给当地分公司的设施。当地团队接手驻站，总部机动编制不因过城永久减少。来源：S01 §04、20，p4、15。

**FR-META-03 有限跨城协作。** 前两城各选一项分公司协作，本局最多两项；旧城不持续无限产出。远征完成后协作转化为可选开局支援的解锁资格。来源：S01 §20，p15。

**FR-META-04 成功、失败与保留。** 完成第三城为成功；期限耗尽未达标、必要经营支出不足或主动终止进入相应结算。保留已确认知识、已完成研究、分公司成就和此前交接记录；新局重置资金、实物、编制与占领状态。来源：S01 §01、20，p3、15。

**FR-META-05 公平开局与评价。** 新局使用基础资金、人力和工具框架；知识不直接揭示新实例答案，工具解锁扩充候选池，开局支援共用有限预算。评价覆盖稳定接管、源头、人员损失、额外回收和支援使用，不仅按金币评价；评分公式待定。来源：S01 §20，p15；D-10。

## 07 界面、存档与数据需求

### 7.1 玩家界面

**FR-UI-01 城市地图可读。** 分开显示队伍位置和公司控制，地点类型、设施/停业、来源、扩张目标和选中封控边都有可区分标记，不只依赖红绿颜色。来源：S01 §21，p15。

**FR-UI-02 节点与线路详情。** 节点展示委托、规则、接管条件、库存、营业与支援；线路展示归属、通行、异常覆盖和恢复办法。路线预览包含完整成本及已知风险。来源：S01 §21，p15。

**FR-UI-03 准备方案反馈。** 同屏组织事务位、岗位、人力、工具占用和预计资金；冲突在锁定前指出，未知任务展示保守调查的明确边界。来源：S01 §21，p16。

**FR-UI-04 现场位置与操作对象。** 地图、当前房间、手牌和已知风险可同时查看；区分正在查看的房间与队伍所在房间，卡牌提交前再次明确作用对象。来源：S01 §21，p16。

**FR-UI-05 风险与日志。** 提交前预览已知风险；未知内容只给已有先兆，不泄露答案。日志含行动前条件、基础收益、触发规则、护符消耗和最终变化；异动阈值、封门和撤离有提示。来源：S01 §21，p16。

**FR-UI-06 视听可替代。** 关键声音线索同时提供文字或图标，允许关闭闪烁和突然高音量效果。美术优先可读卡面、地点识别、节点状态、危险预告与撤离反馈。资源制作方式采用 S03 的 AI/手绘润色及简单 BGM。来源：S01 §22，p16；S03。

**FR-UI-07 行动前的已知信息预览〔本次吸收及用户补充〕。** 选牌或基础动作时，显示真实目标、行动成本、可执行的基础效果、已有可靠信息支持的触发条件及剩余次数；点击后按当前状态重新校验。未知守则只显示已获得的先兆与不确定性，不能将“暂无已知危险”写成“安全”或“零损失”。不得借风险数值、按钮启用状态、排序、目标高亮或提示差异泄露隐藏答案；物理合法性可以公开，秘密规则不得作为暗中禁用合法动作的理由。运输确认和路线比较同样遵守此信息边界，仅显示已知运输后果，具体按 FR-SPR-05 执行。玩家未确认但已观察到的事实与已确认守则分开呈现。来源：FR-RULE-03/04、FR-UI-05；S04、S05、S06。验收：AC-26。

**FR-UI-08 轮末后果分项预览〔本次吸收〕。** 结束本轮前，按 FR-RULE-07 的真实顺序展示已公开敌影意图、灯光结束、异动变化与阈值袭击、护符可抵挡项及封门剩余轮次。全部条件已知时，可给出确定的预计净变化；存在未知条件时标注“基于已知信息”，保留不确定部分，不能承诺最终精确值。高危险结果与最后撤离机会重点提示。不得引入 Demo 的独立压迫 / 防护资源，也不得把护符等同于通用减伤。确定性预览和实际结算应一致，归零后停止展示后续补救为有效收益。来源：FR-FLD-05/08/09、FR-RULE-05/07；S04、S05。验收：AC-27。

**FR-UI-09 任务、路线与撤离条件可见〔本次吸收〕。** 将当前委托的已获证据、待确认结论、目标物发现 / 携带 / 交付状态，以及可用出口和剩余轮次列为简短清单。仅对任务已定义的可计数目标显示进度；完成调查不得替代实物交付、自动传送出房或跳过该行动的规则后果。地图清楚区分当前位置、已知可达路线、当前查看目标及已知撤离费用；显示“调查完成”“已携带”“成功撤离”“已交付”的不同阶段。返回基础入口的免费撤离规则继续适用。来源：FR-MAP-01/03、FR-FLD-05/06、FR-ECO-01、FR-UI-02/04；S04、S05。验收：AC-28。

**FR-UI-10 奖励与升级比较〔本次吸收〕。** 领取新工具、升级或装备前展示基础与变更效果、触发条件、作用对象、有效期限、容量 / 配装要求及真实代价。明确“立即可用”“本次借用”“撤出后归库再配装”或该内容实际采用的生效时点；不默认现场奖励都永久加入当前牌组。候选允许按既有规则拒绝，并说明拒绝后的去向；同一来源的候选、选中或拒绝结果应被记录，不因重新打开界面、重返或读档重新抽取。被发现但未入包的唯一实物仍按 FR-ITEM-03 留在原位置，不能被通用奖励界面删除。来源：FR-CARD-01/02/03、FR-ITEM-02/03、FR-SAVE-04；S04、S05。验收：AC-29。

**FR-UI-11 分阶段情境引导〔本次吸收〕。** 首次准备出勤、选牌、发现证据、候选验证、选取成长和撤离时，提供贴近当前操作的短提示；已完成阶段不反复遮挡，可收起并从帮助入口重看。提示中的动作数、手牌数、效果和计数周期与当前有效配置一致；不得写死 Demo 的两行动四手牌或显示尚未发现的规则。关键风险提示独立于教程，收起教程不取消危险反馈。来源：FR-UI-04/05、P-FIELD；S04、S05。验收：AC-30、AC-20。

**FR-UI-12 模仿内容与豁免边界可见〔本次吸收及用户补充〕。** 模仿牌动态显示当前参考指令、实际执行地点 / 对象、合法库存和用途条件，以及采用方案的成本、次数、耗尽或重置周期；不可用时说明已知原因。区分不会产生的原行为标签与仍会发生的取得、携带、灯光、恢复等结果事件；只预览玩家已知的对应后果。组合来源、原牌基础效果和规则追加奖励分别列出，不能让玩家误以为复制旧房最终收益。当前显示每次出勤耗尽的验证方案；疾走后保持参考指令并更新当前地点、库存和已知后果。D-06 尚未明确的行为不得用文案暗自补全。来源：FR-MIM-01 至 04；S04、S05、S06。验收：AC-30、AC-15。

### 7.2 存档与数据契约

**FR-SAVE-01 安全保存时点。** 支持经营日准备阶段和现场回合边界保存；退出时提示最后成功保存位置。自动续玩采用 FR-SAVE-05，槽位及非安全边界退出行为仍见 D-11。来源：S01 §21，p16；S04、S05 本次吸收。

**FR-SAVE-02 完整恢复〔基线及本次吸收细化〕。** 恢复地图、经营日、派遣及预留资源、物品位置、合同/已付里程碑、规则/确认/计数、人员状态与随机进度，并恢复当前手牌和牌库顺序、模仿参考与耗尽、装备组合额度、待选奖励和稀有揭晓来源的使用记录。反复读取不能重新抽取同一操作结果或再次领取奖励。来源：S01 §21、25，p16、18；S04、S05。

**FR-SAVE-03 数据字段可追踪。** 城市保存种子、阶段、日、节点边、活跃源、预告和目标；节点保存实例规则、合同、库存、设施、岗位、入侵来源；合同、物品、员工、卡牌和规则按原设计 §25 保留独立身份及状态。来源：S01 §25，p18。

**FR-SAVE-04 随机边界。** 随机只影响明确允许变化的内容，不隐式改变已确认规则。仅保存初始种子不能代替保存足以恢复当前随机进度的信息；同一存档、同一操作序列应得到一致结果。来源：S01 §25，p18；实现方式由技术设计决定。

**FR-SAVE-05 自动检查点与继续游戏〔本次吸收〕。** 在经营日准备方案的有效变更、现场完整回合边界、奖励选择完整提交、出勤完整结算及城市交接完成等安全状态后自动保存；保存点必须晚于该事务的全部扣费、移交、计数和随机状态提交。奖励画面可在候选已生成且尚未选择的完整状态保存，但不得重抽候选。开始界面在存在可读存档时显示“继续游戏”及城市 / 经营日 / 现场位置、最后成功保存时间；没有存档时明确显示新局。仅在保存成功后更新已保存提示，失败给出提示并保留上一份完整记录。恢复不能重复支付、领取、重置组合次数或回退随机进度。现场回合中尚未达到检查点的动作不承诺立即落盘，退出时应明确尚未保存的范围；精确退出、备份和多槽策略仍见 D-11。来源：FR-SAVE-01 至 04、NFR-04；S04、S05。验收：AC-31、AC-18/23。

## 08 质量与发行要求

**NFR-01 双平台验收〔用户补充〕。** Windows 与 macOS 均应能安装/启动、完成核心交互、保存并继续游戏；最低系统、硬件、分辨率及 Mac 架构范围必须先定，再选择代表性机器验收。Steam 发布包按平台分别验证。来源：S02；边界 D-12。

**NFR-02 可解释性〔基线〕。** 可靠文本、界面预览与真实结算一致；违规后果可由日志追溯到具体规则、时点和对象。关键声音不能成为唯一解谜信息。来源：S01 §15、21-22，p12、16。

**NFR-03 内容验证〔建议〕。** 对新增合同、卡、物品和规则检查引用有效、必需字段完整、唯一标识不冲突及兼容组合合法。校验方式不预设框架，未通过的内容不得进入团队认定的发布候选版本。

**NFR-04 保存可靠性〔建议〕。** 保存格式带版本信息；保存中断不损坏上一份完整存档；损坏或不兼容存档给出可理解提示。备份、迁移及跨版本支持政策待 D-11 确定。

**NFR-05 性能目标〔待定〕。** 启动、界面响应、日终、生成、保存加载、内存及安装体积需要在目标设备确定后制定预算。本文不虚构“所有设备 60 帧”或未经测试的时延指标。

**NFR-06 发布边界〔建议〕。** 首发前完成双平台代表机器测试、可追踪版本构建、安装后基本运行及最终需求回归。云存档、成就等额外 Steam 功能只有被明确选入范围后才形成验收义务。

## 11 验收场景与追踪

以下为根据基线推导的验收用例，当前状态均为**未执行**。固定数据用例验证规则，不代替真实玩家体验测试或全局平衡结论。M 表示最小验证阶段至少覆盖；F 表示完整三城阶段覆盖；具体执行工具由技术设计决定。

**AC-01 人力与唯一资源冲突〔M〕**
给定 6 人、2 事务位，安排两支各 2 人的队伍再安排 3 个驻站岗位；事务位合法但人力超额，锁定必须明确指出人力冲突。另测同员工、同工具或唯一目标被重复分配。完整模式另测三队占满 6 人后无法驻站。修正后只扣一次费用，保留唯一预留。对应：FR-DAY-02/03、FR-STAFF-01/02/03、FR-DSP-01/05。

**AC-02 锁定后的信息隔离〔M〕**
上午锁定保守调查和手操；手操获得标准回收必需证据并提前撤离。已派任务不自动升级，不能重排；次日归档证据可受理标准回收。本日依赖尚未完成工程的出勤不能通过改结算顺序成立。对应：FR-DAY-04/05、FR-DSP-02/04/05。

**AC-03 单次日结与账目〔M〕**
准备阶段反复查看和修改未提交方案不推进日期；提交后按准备、锁定、执行、结算四阶段运行。按原文测试参数：晨间 12，双队预付 2，合同分别 5 和 4，两点收入 2，基本支出 2，日终为 19；手操空撤且无合同收益时为 14。交换无依赖任务顺序，余额、库存、日期与奖励一致。对应：FR-DAY-01/06、FR-ECO-01/02/03。

**AC-04 新建与修复时点〔M〕**
本日新建点无当日收入与封控；晨间失效但已锁定驻站的旧点当日修复后无补发收入，可按条件参加当晚封控。缺岗点不得仅因修路成为有效点。交接计数用例在 D-01 冻结后补齐。对应：FR-DAY-07、FR-NODE-02/03。

**AC-05 扩张顺序不影响结果〔M〕**
建立至少两条预告箭头，其中一条切断枢纽，另一条有有效封控。交换箭头执行顺序，最终入侵、封控、设施和网络必须相同；刚入侵点不得当晚二次传播。对应：FR-SPR-01/02/03/04。

**AC-06 源头交付不撤销运输后果〔F；M 用线路规则覆盖基础语义〕**
在相关运输条件已知的场景中，运输前正确展示会侵入的节点；玩家确认违规运输并在同日交付源头。该源头未执行的敌方箭头取消，已经登记的运输入侵保留；换封装或合法路线可避免相应后果。条件未知的预览另按 AC-26 验证，实际违规仍产生相应运输后果。对应：FR-SPR-04/05/06、FR-ITEM-04。

**AC-07 断联、维护与旧点回访〔M〕**
已接管点断联后保留设施、发现、库存和合同；通过环路或抢修恢复合法条件，不重复付基础建设费。对已知入侵按确认规程委派常规维护，不重新生成已回收源头。重返默认服务界面，旧规则和领奖不重置；恢复通行不等于解除线路守则。对应：FR-MAP-01、FR-NODE-02/03/05/06、FR-DSP-02、FR-SPR-04。

**AC-08 管理路线确实可完成〔M+F〕**
为选定种子给出逐日管理路线与混合路线，列出人力、费用、证据归档、工具次数、工程次日起效和交接条件。最小版使用 2 事务位，完整版使用 3 事务位，不得混用参数。检查当前阶段规定的起步任务、环路、多线枢纽或源头替代路线。缺工具、自锁或期限内无合法日程的反例必须被识别，不得仅凭地图连通判通过。完整三城还必须通过 AC-33 的连续验证，单城检查不能替代它。对应：FR-MAP-02/03/04/05/06、FR-DSP-04。

**AC-09 委派耗尽工具校验〔M〕**
规程需要两次豁免，但仅有一次可用模仿，或需要车票而实例已耗尽；锁定前说明缺口。补齐后仅消耗真实次数；不得领取未选隐藏组合收益。对应：FR-DSP-03/05、FR-CARD-04、FR-MIM-04。

**AC-10 城市与现场确认不双奖〔M〕**
用已归档证据在城市确认，再进入现场查看同一规则，不再发放首次确认奖励。错误候选保留且不能按错误规程回收。证据不足不得提交；额度测试按 D-04 的最终口径补齐。对应：FR-DSP-06、FR-RULE-03/04。

**AC-11 末轮撤离与失败重返〔M〕**
存活队伍最后一轮回入口，先免费撤离即成功保留合法成果；继续结束轮次则按封门规则处理。失败的必需合同物可回收且只有一份，旧证据保留，重返不重发已领奖励。对应：FR-FLD-01/05/06/07。

**AC-12 无效操作不扣费〔M〕**
无通路移动、容量不足时拾取已发现物品或收容条件不满足的封装被拒绝并显示原因；查看信息免费。搜查先发现物品后拒绝入包，不把已经执行的搜查改为免费。没有搜查/封装牌时仍可按基础费用完成合法动作。旅馆放置房间按参数扣行动和墨水，首次进入新房获得墨水，重返不重复领取。对应：FR-FLD-02/03/04、FR-ITEM-02/03/04。

**AC-13 心志归零立即终止〔M〕**
一次行动依次产生负面与正面后果；先前后果使心志归零后立即失败，不执行后续补救。检查全城→线路→地方顺序、行动前现金与获得后物品分别使用正确状态。对应：FR-RULE-01/05/06。

**AC-14 护符与轮末边界〔M〕**
同一动作触发多个可抵挡后果，逐项消耗；阈值袭击不得被护符抵挡。异动在行动中增加达阈值立即处理，轮末按规定顺序执行敌影、灯光、异动和封门。对应：FR-FLD-08/09、FR-RULE-07。

**AC-15 模仿的收益与代价边界〔M〕**
安全房先搜查，再用疾走沿合法路径到镜厅：途中风险逐格结算，模仿参考仍为搜查；随后模仿领取镜厅尚有的唯一物而绕过“搜查”动作惩罚，仍触发获得/携带事件并按出勤方案耗尽。镜厅为空时不得复制旧奖励；没有参考时疾走不创建参考；若随后进入新楼层，则按换层规则清空参考。另测普通/模仿休息共用次数、护符仍受上限约束，以及其他非白名单行动牌更新参考后模仿不可用，不回找旧搜查。对应：FR-MIM-01/02/03/04、FR-CARD-05、FR-RULE-02。

**AC-16 实物生命周期〔M〕**
发现物品但拒绝入包不触发获得；后来拾取不新建实例。放回、重返、普通或模仿搜查都不能刷新库存。研究消耗后不能继续出售或装备；封装红箱仍保留红色身份。对应：FR-ITEM-01/02/03/04/05、FR-ECO-01/02。

**AC-17 构筑与借用牌〔M〕**
选择或拒绝新工具后牌组合法，删除不低于下限；现场获得牌进入手牌后仍支付出牌成本。出勤结束移除借用资格，不将稀有实例复制给另一队；疾走逐格结算风险。对应：FR-CARD-01/02/03/05、FR-STAFF-03。

**AC-18 读档不重抽、不重付〔M+F〕**
分别在准备阶段及锁定后的现场回合边界保存，记录同一操作序列的结果。载入重做后随机结果、任务、计数、工具预留、库存和余额一致；确认、领取或日结不能重复付款。对应：FR-SAVE-01/02/03/04、FR-RULE-02。

**AC-19 交接与跨局保留〔F〕**
最后一日扩张后核验源头和营业点；失效点不计入。跨城编制不因驻站永久减少，旧城不无限付钱；第三城失败仍保留前城成就、已确认知识与研究，新局不继承实物和占领。另测协作数量上限、远征完成后转为开局候选资格及共同支援预算；家族知识不直接确认新实例答案，预算口径按 D-10。对应：FR-DAY-08、FR-META-01/02/03/04/05。

**AC-20 无口头提示的体验验证〔M+F〕**
邀请未编写该机制的人游玩，记录任务选择、卡牌使用、线索如何改变决策、两套合理牌组、撤离时点、手操/委派用途、布局差异、断联替代方案、未使用功能及失败原因理解。记录各阶段和完整远征耗时，对照暂定 2 至 3 小时目标。另外记录规则确认前后实际行动序列：是否长期只剩“点灯再搜查”等固定顺序，是否存在因房间目标、携带条件、剩余轮次和不同组合而改变选择的情况。至少比较两套可行组合的决策差异，不以数值更大代替玩法变化；出现单一稳定最优循环时登记内容或平衡问题，不临时针对玩家生成克制守则。若玩家只猜答案、总等同一张牌或不理解后果，则登记问题，不把小样本当市场验证。对应：PR-01/02/04、FR-NODE-04、FR-RULE-08；S01 §24 p17。

**AC-21 界面与声音替代〔M+F〕**
只查看房间而不移动时，卡牌目标仍明确指向实际对象；检查路径费用、岗位冲突、风险预览和日志一致。静音且关闭闪烁后，关键线索与危险提示仍可理解。对应：FR-UI-01/02/03/04/05/06、NFR-02。

**AC-22 双平台基本流程〔F〕**
在已确认规格的 Windows 与 Mac 真机运行发布候选包，完成新局、核心交互、撤离、保存、退出与继续。记录设备、系统、构建版本和异常；本用例尚未执行，且不包含未选入范围的云同步。对应：PR-03、NFR-01/05/06。

**AC-23 数据和存档异常〔建议；M+F〕**
构造无效内容引用、重复 ID、保存中断及不支持版本的存档，验证内容校验、旧完整存档保护和错误提示。具体恢复策略待 D-11 冻结。对应：NFR-03/04、FR-SAVE-03。

**AC-24 风险缓冲与经济失败〔方案未定；M〕**
验证失败恢复造成的人力缺口、扩编新增支出、紧急支援是否可重复领取，以及必要支出不足的失败路径。金额与支付/成功优先级按冻结后的 P-FAIL、D-03 执行，评价规则按 D-10。对应：FR-STAFF-04、FR-ECO-04/05。

**AC-25 首次接管门槛〔M〕**
到达地点或完成普通搜索后，缺少合同规定结论或关键物时不得自动获得建设资格；满足全部资格并支付成本后才进入施工。若选入非异常合作点模板，则按公开签约或运输条件验证，不强制附加现场回收。对应：FR-NODE-01、FR-ECO-01。

**AC-26 已知预览与未知信息隔离〔M〕**
准备两个公开状态、已获线索和候选记录相同但隐藏守则不同的现场，比较提交动作前的牌面、数值、按钮状态、排序和目标高亮；除已有公开先兆外不得出现差异。分别在仅观察、取得可靠线索、正确确认后检查标签。全部条件已知时，目标、消耗、计数与实际动作一致；未知时显示不确定性。改变查看房间不改变队伍真实位置和作用对象。另准备公开状态相同、未知运输规则不同的两条测试路径：运输预览不得提前标出秘密规则导致的侵入节点或精确损失，也不得因此改变按钮可用性；可以显示共同的已有线索和不确定性。玩家满足既有条件时可选择运输，实际后果按各自规则结算并记录。取得相关知识后，预览应正确显示已知受影响节点；混合已知与未知条件时不得把已知部分当作完整安全保证。对应：FR-SPR-05、FR-UI-07、FR-UI-05、FR-RULE-03/04、NFR-02。

**AC-27 轮末预览与终止顺序〔M〕**
构造公开敌影、护符、灯光、临近阈值异动和末轮封门；核对预览顺序与 FR-RULE-07 一致。护符只能抵挡允许项目，阈值袭击不能用护符扣减。增加或移除一个公开条件后预览更新；先前伤害归零时后续恢复不得显示为可救回。含未知守则时不出现伪精确总损失，也不从提示差异推断答案。最后一轮已到入口时可先免费撤离。对应：FR-UI-08、FR-FLD-05/08/09、FR-RULE-05/07、NFR-02。

**AC-28 目标完成不代替撤离与交付〔M〕**
依次检查取得线索、确认规程、发现目标物、入包、回入口、撤离、交付的清单状态；拒绝入包不能显示已携带，现场携带不能显示已交付或提前到账。一次取得目标的动作仍完整处理携带风险与心志归零，不因“目标完成”跳过后果。已知出口、通路与成本正确，不把付心志跳过房间作为基础撤离。对应：FR-UI-09、FR-FLD-05/06、FR-ECO-01、FR-ITEM-03、FR-RULE-05。

**AC-29 成长组合与领取唯一性〔M〕**
用冻结内容表选取两套实际可行组合，比较它们如何改变行动顺序或资源取舍；不要求存在 Demo 的调查条或同名遗物。核对奖励前后差异、借用期限、生效时点、额外成本与容量；同一实物不能同时归两队，拒绝入包的实物仍在原房间。对首次触发、同房重进、普通与模仿、装备移交、读档和委派逐项检查共享额度与触发边界；未获批的组合不凭委派虚构收益。反复打开同一奖励、拒绝、重访及读档不能重抽或重领。对应：FR-CARD-06/07、FR-UI-10、FR-CARD-01/02/03/04、FR-ITEM-01/03、FR-SAVE-04。

**AC-30 情境引导与模仿解释〔M〕**
首次游玩按准备、出牌、证据、验证、成长、撤离顺序查看提示；收起后主流程可操作，帮助可重看，关键危险仍提示。修改测试配置后动作数和手牌文案同步更新。模仿参考合法牌、无参考、换房、疾走后、跨轮、换层及耗尽等状态，界面与选定方案一致；疾走后保留参考并更新实际地点与库存，只显示已知豁免与后果，不复制旧奖励或暗示未知规则。模仿成功打出后不能在本次出勤重洗回来，无效操作不耗尽；其余未决语义按 D-06 解决后补齐用例。对应：FR-UI-11/12、FR-MIM-01 至 04、FR-CARD-05、FR-FLD-02。

**AC-31 自动续玩与事务完整性〔M+F〕**
在准备阶段、现场回合边界、奖励待选 / 已选、出勤结算后及跨城后分别退出并重启正式客户端；继续入口正确标出进度，牌组、实物、计数、余额、候选与随机进度一致。对扣费 / 领取 / 交付 / 计数写入中断注入故障，只能恢复到完整旧状态或完整新状态，不能恢复部分事务；重做同一操作序列不重抽、不重付。模拟保存失败，界面不得显示保存成功且上一份完整记录可用。回合中退出按 D-11 选定行为执行并检查未保存范围提示。网页刷新试玩只能作为体验参考，不能算本用例通过。对应：FR-SAVE-01/02/03/04/05、NFR-04、FR-CARD-07、FR-UI-10。

**AC-32 常规推理与稀有揭晓的边界〔M〕**
普通调查只返回允许取得的可靠线索，实践留下真实日志，候选确认仍适用原配额和错误记录。对一个符合条件的稀有来源，按冻结内容表消费一次机会并揭晓一条尚未确认的合法规则实例，更新确认与已知预览；不揭晓其他地点或下一局的规则，不替代封装、运输与交付。纯揭晓来源无目标时不扣费、不消耗机会；复合卡或事件的其他效果与成本按已展示的冻结条目核对。已确认规则不能再次消费揭晓机会刷奖励。保存读取、现场切换到城市确认或再次访问来源不重复揭晓 / 奖励，既有错误候选和证据保留。是否发放首次确认奖励按该来源明确的内容规则检查，不得双奖。在同一组任务中验证没有取得稀有来源时，仍存在依靠普通实践与证据推进关键目标的路径。对应：FR-RULE-09、FR-RULE-01/03/04、FR-DSP-06、FR-SAVE-02、FR-META-05。

**AC-33 三城连续可完成〔F〕**
为同一完整远征生成结果分别提供管理路线、混合手操路线的连续三城日程。逐日列出资金、人力与恢复状态、工具与实物、证据、事务位、建设生效及交接条件；第一城的真实交接结果必须成为第二城输入，第二城同样传递到第三城。任何合法补充都须有明确来源、成本和取得时点，不允许测试数据补满资金、工具或人员。构造每城在独立初始配置下都能完成、但第一城交接后的工具或资金无法支持第二城且后续无合法补充的反例，完整生成检查必须拒绝它；仅证明另一种模式可完成也不能替代两类路线的要求。按城生成时另以不同真实交接状态验证后续可行路线；生成失败按 D-08 处理，不改写已经生成的地图或规则。记录可行路线、交接状态和失败原因；玩家偏离可行路线后浪费资源或超期，仍可按既有规则失败。该用例定义要求，尚未执行。对应：FR-MAP-05/06、FR-META-01/02/03、FR-STAFF-01/02/04、FR-DAY、P-STAFF、D-08。

## 13 四人协作、冻结与变更

### 已知团队约束

团队共四人，均可通过 AI 提出和完成工作，在 GitHub 协作。最新设计明确不设固定岗位或系统分工；本文不指定某人永久负责某模块。来源：S01 §24，p17。

用户要求设计先行。需求、规则边界和技术方案经过确认后，再进入被授权的实现或验证阶段。原设计建议通过纸面推演、现场验证、单城验证、三城验证逐步扩大内容；这些阶段不构成未经确认就开始开发的授权。来源：S03；S01 §23，p17。

### 建议的冻结门槛

1. 四人确认完整目标、最小验证范围和非目标；区分行为约束、暂定参数和内容预算。
2. 落实已确认的 D-05，解决影响状态与接口的 D-01 至 D-04、D-06，并确认 D-08、D-09、D-11 的设计方案；其余待定项明确所属阶段。
3. 纸面推演混合手操、管理路线和失败恢复路线，覆盖资金、人力、工具、证据归档、建设生效和期限。
4. 每项进入实现的需求具有编号、来源、可观察验收结果和关联决策，不以“看起来可玩”代替验收。
5. 形成经团队确认的技术设计，再按获准范围实现；未冻结项明确为验证实验，不能悄悄变成首发承诺。

以上为本文提出的流程建议。分支、PR 和他人检查仍可用来核对实现是否符合已批准设计，不要求团队改成固定岗位或边做边扩范围。
