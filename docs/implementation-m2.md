## 当前实现范围

客户端沿用 Godot 4.7.2 .NET + C#，SDK 由 `global.json` 固定为 10.0.401；客户端目标框架为 `net8.0`，独立测试程序为 `net10.0`。`Core/` 不依赖 Godot，界面与自动检查使用相同的城市、现场、实物及存档引擎。

- **固定单城。** 七节点为公司总部、暮灯旅馆、北街枢纽、白榆医院、红箱源头、南街枢纽和公共协作点；两条双向路线在医院汇合。初始 16 资金、6 人，每日 2 事务、最多 1 队手操，5 日内交付源头并拥有 2 个有效营业点。没有扩编。新建次日生效，驻站及连通条件参与营业和交接检查。
- **两种隐藏真值、两种公开报价。** 旅馆采用同一“镜中住客”实例的 A/B 受控变体：A 在未照明镜面房正常搜查时触发，B 在本次出勤同镜面房第二次及以后正常搜查时触发、与灯光无关；后果均为 2 心志反噬，可由 1 护符抵挡。灯具报价为开局公开固定的 6 或 2。真值变体与下文的经营路线 A/B 是两个独立维度。种子影响实际抽牌进度；固定骨架及这组内容不能作为城市生成器的可完成性证明。
- **传播独立。** 默认账例不开启传播压力，不收交通附加费，也没有强制抢修。标题可单独开启压力场景；其传播、封控与线路后果需要另验，不能沿用无压力日程余额作为保证。
- **统一经营结算。** 准备阶段组队、驻站和安排工程；锁定时预付并保留人员、工具和支援占用。所有队伍共用日终结算。预付后的资金预测不重复扣同一笔费用；合同、现场零钱、营业与基本支出分别入账。空计划也会推进经营日。
- **现场与推理。** 每轮 3 行动、5 个普通手牌槽。正常搜查次数按房间及出勤记录，离开再进入不重置；新出勤重置行为次数，真实库存不刷新。旅馆第一柜只提供有限寻物记录并定位第二容器，后续仍需实际搜查或模仿取得合同物。旧录像不能直接区分 A/B；暗处首次正常搜查的实际反应可以构成对照观察，护符抵挡伤害仍保留事件记录。
- **模仿与确认。** 模仿使用当前位置及真实库存，不产生正常搜查行为、不增加 B 次数；疾走及灯具支援保留参考。每队最多 1 张模仿，每次出勤耗尽。现场所有规则共用每轮一次候选提交；城市同日已判断的该条不能再转现场提交；错误候选及唯一确认奖励跨模式保留。

## 唯一工具、灯具与失败

| 内容 | 当前行为 |

| 有限补充 | 唯一供应商耗材；3 资金、1 人、1 事务，日终补 1 次，次日才可使用；满额不接受补充，供应耗材不刷新 |

| 医院封装 | 公开要求本轮照明；实际封装仍消耗隔离工具，不以完成调查代替收容和交付 |
| 灯具出售 | 唯一灯具占 1 格；封装并带回后可登记日终出售，处置提交前可取消；不在现场取得时提前付款，不重复出售 |
| 未封装暂存 | 满足既有运输条件时可带回仓库；不产生收入或支援，不能直接安装或出售。总部补封装占 1 人、1 事务和 1 次已有隔离余量，日终完成，次日可用；不借用同日才补入的次数 |
| 安装与支援 | 封装灯可在后续准备阶段安装于有效驻站点；安装不额外占事务或资金。锁定前给手操队预留支援，现场实际使用一次免费点灯，产生正常点灯及灯光事件、异动最低为 0，不覆盖模仿参考。每日额度、安装归属和队伍预留均按实例记录；拆装或读档不刷新已用额度 |
| 失败遗落 | 带入工具和现场取得的全部实物均按唯一位置遗落，现场未撤出零钱丢失，已消耗次数不返还。员工恢复一经营日；可安排不携工具的手操队重返并拾取已发现的遗落工具 |

模板牌组仍可在准备阶段免费调整至 10–16 张，模仿最多 1 张。这是出勤前配置实验；付费工具站的替换、删牌、升级服务，以及完整成长候选与组合内容尚未完成，不能据此认定 FR-CARD-03 或 AC-29 已通过。

## 存档 v2 与继续游戏

正式 M2 使用 Godot `user://profile-m2/save.json`，上一完整备份为同目录 `save.json.bak`。UI 验证使用 `user://ui-validation-m2`；截图模式使用独立预览路径并跳过保存。历史 `user://profile` 不作为 M2 正式读写目录。

存档封装 `FormatVersion` 和游戏状态 `SchemaVersion` 均为 **2**。不兼容旧 v1，不自动填默认值迁移，也不覆盖不支持版本的原档。主档损坏时可尝试完整备份并明确提示；格式版本不支持时拒绝加载，不以较旧备份默默替代。保存采用同目录临时文件、完整写入及 `Flush(true)` 后原子替换，首存原子移动，SHA-256 校验内容；只有提交成功才更新保存时间和成功提示，失败保留上一完整记录。

检查点包括准备方案有效变更、完整锁定及现场开始、现场完整轮界、候选判断及奖励完整提交、完整出勤归队、日终和本单城交接。现场轮中退出恢复**最后一次成功的完整检查点**：没有更晚检查点才回到轮初；若本轮已有完整确认奖励检查点，则从该较晚状态继续，不能保留奖励同时回退成本。退出提示最近成功位置及其后未保存动作的范围。

新增状态随完整快照保存，包括固定五槽及空槽、抽弃牌和随机进度、模仿及耗尽、房间正常搜查计数、有限柜与对照样本、观察和归档、错误候选及跨模式配额、供应商和工具余量、工程及预留、实物归属和处置、灯具安装位置及日支援额度、待日结摘要。读写两侧检查版本、重复 ID、引用、枚举和合理数值范围。

`SaveTests`、`M2SaveTests` 覆盖新增状态往返、随机序列一致性、原子提交前故障、旧/新完整快照、主档损坏回退、未知版本保护和非法状态拒绝。`M2IntegrationTests` 另保存真实现场的较晚确认奖励检查点，恢复后继续轮末抽牌和下一次正常搜查，比较随机进度、卡槽、库存、护符及心志。存储层构造快照与真实引擎继续运行是两类证据，不能互相替代；尚未声称磁盘断电或所有操作系统上的异常场景已验证。

## 2026-09-16 异动阈值修正

接手基准为 `391b9ff543dde4d39fec1790186e6acc1a164567`。策划 v0.2 第 10 节规定异动达到 8 后损失 3 心志并**回落到 4**；旧实现及两种预览却使用减 4，导致 7 + 2 后剩 5，大额单次增加还可能重复袭击。

现在实际结算、动作预览、轮末预览共用同一阈值计算：每项增量完整加入后检查一次，达到阈值便回到 4，超量不保留。后续独立规则的增量仍单独检查；护符可取消原规则的可抵挡后果，但不能抵挡阈值袭击。预览中的心志最低为 0，归零后不再处理后续恢复、轮末增长或换轮。未知规则继续只给条件说明，不泄露隐藏增量或确定净损失。

| 输入 / 顺序 | 预期结果 |
| --- | --- |
| 6 + 1 | 异动 7，不袭击 |
| 7 + 1、7 + 2、7 + 9 | 异动 4，各袭击一次、损失 3 心志 |
| 初值 7，两条规则分别 +2、+4 | 每项分别触发，最终异动 4、合计损失 6 心志 |
| 已知灯灭规则使 7 + 2，队伍存活 | 先回到 4，再普通轮末 +1，最终 5 |
| 心志 1 / 2 / 3 遭阈值袭击 | 预览及实际均为 0，立即失败，后续效果停止 |
