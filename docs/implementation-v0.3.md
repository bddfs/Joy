# v0.3 单城验证版实施记录

日期：2026-09-15。需求依据：`origin/main` 的 `ecc6980`（需求 v0.3）；本轮用户明确要求开始开发。本文记录本构建行为，不修改原需求中的“暂定”和“待定”。

## 交付范围

已建立可运行的 Godot 4.7.2 .NET / C# 工程。`Core` 仅依赖 .NET；Godot 界面调用同一份 `GameState` 和 `CityEngine` / `FieldEngine`，没有另外一套展示用资源。存档保存完整状态，委派与手操共享实物、合同、规程和人力。

当前是 **单城最小可玩验证版的第一轮实现**，不是全部 M 验收完成，更不是完整三城游戏。内容为固定七节点雾港：总部、旅馆、医院、双交通枢纽、合作站和源头。初始资金16、员工6、每日2事务、最多1手操；5日内交付源头并让2个服务点有效营业。

- 城市：双向环路、人员自动配队、工具实例预留、驻站与封控、保守调查、标准回收、手操、接管、维护和线路抢修。锁定一次预付，所有队伍统一日结。空排也推进经营日。
- 现场：每轮3行动/5手牌、12张10种牌、入口免费撤离、查看与真实位置分离；基础移动、搜查、拾取、放下和封装；旅馆一间可放置侧房，医院采用固定房网。
- 守则：6条验证规则，可靠线索、原始告示、实际观察、候选确认；每规则/行动一次触发、护符边界、异动即时袭击、公开敌影与封门期限。
- 模仿：在当前房间执行白名单基础指令；不复制旧收益或原行为标签，实际携带结果仍触发；疾走逐格且保持参考；本次出勤耗尽，无效操作不扣费、不耗尽。
- 实物：4件异常物、2件各2次的封装工具、1件可搜索得到的一次稀有揭晓透镜；背包/房间/仓库/交付单一位置。拿到目标不代表交付。稀有揭晓仅作用于当前现场合法未确认实例。
- 界面：调度、档案、工具模板、账本、现场地图、手牌、已知预览、背包、完整行动日志、标题继续入口及手册。未知守则不参与风险高亮或隐式禁用。
- 存档：准备有效变更、锁定并开始现场、完整回合边界、完整归队、日结后保存；SHA-256校验、同目录临时文件、刷盘后原子替换，保留上一完整备份。

## 验证版临时决策

以下是为本轮可运行实验采用的明确方案，**不代表团队冻结了最终设计**。

| 决策 | 本构建采用的规则 |
| --- | --- |
| D-01 旧点修复 | 晨间已锁驻站的旧点修复后可参与当晚封控和交接；不追领收入。本日新建不参与三项资格 |
| D-02 失败物品 | 带入物返仓，保留已消耗次数；现场取得物在失败房间遗落，唯一记录保留；现场零钱清零，员工下一整日恢复 |
| D-03 必要支出 | 基础2/日，已含驻站；先判断是否支付得起再判断成功，支付后余额0合法；一次支援+6，记录使用但不实现最终评分公式 |
| D-04 确认配额 | 现场所有规则合用每轮一次；城市每规则每日一次；共享确认/领奖/错误记录，两个配额分别记数 |
| D-06 规则契约 | City→Line→Local，同范围按Order再ID；每条每行动最多一次、无递归规则连锁；心志上限12、异动下限0；每房休息2次为地点实例额度 |
| D-07 模仿 | 1张上限、每次出勤耗尽，无额外心志费；后续需做平衡比较 |
| D-08 生成 | 暂不生成随机城市或三城。固定骨架，种子只影响真实现场抽牌；成功路线不冒充生成器证明 |
| D-09 验证内容 | 初始2个独立SealKit各2次，一次封装消耗1次；调查每次一条可靠线索；标准回收须地点与途经线路要求完整且有工具。合作站公开签约，接管仍付4资金、占1人1事务1日 |
| D-09 额外基础细节 | 放下0行动；稀有揭晓1行动/1透镜次数，不给普通确认奖励；第4/8轮若在非入口且无敌影则预告一名，最早下一轮末攻击 |
| D-11 续玩 | 单槽+1备份，主档损坏回退时提示；未知版本拒绝覆盖/加载，不实现迁移。现场回合中退出回上一边界，不把零散扣费单独存盘 |
| D-12 客户端 | 本机先验证Windows x64、Compatibility渲染、1440×900窗口，限制最小1280×800；不是最终最低硬件承诺。系统CJK字体回退，当前无音效、闪烁或声音专属线索 |

团队模板配装目前免费在10–16张范围调整，普通工具复用，模仿最多1张；付费工具站删牌/升级、获得候选及组合装备尚未实现。此处是出勤前配置实验，不替代 FR-CARD-03 的工具站服务。

## 实际可完成日程

`Tests/IntegrationTests.cs` 从 `WorldFactory.Create(seed)` 通过公开引擎操作执行，未注入额外资金、工具或已知旗标。路线选择已获得线索支持的正确候选；测试直接指定候选索引不等于自动推理算法。

管理路线：

| 日 | 事务 | 日终结果 |
| --- | --- | --- |
| 1 | 旅馆调查＋源头调查 | 两份线索归档；资金16 |
| 2 | 确认已归档规程；旅馆第二次调查＋源头回收 | 源头交付且停止新扩张；资金20 |
| 3 | 确认旅馆第二条；旅馆回收＋合作站建设 | 旅馆已交付、合作站已建；资金18 |
| 4 | 旅馆建设 | 两点均建成；资金12 |
| 5 | 两点各驻站1人、无出勤日结 | 营业2抵基本支出2，扩张后满足交接；资金12 |

混合路线另开同种子独立初始状态：第1日实际手操旅馆，通过真实牌库打出调查取得两条线索后从入口撤离，同时委派源头调查；第2日确认并双回收，第3日双建，第4日驻站交接。不借用管理路线的任何资产。四组种子验证抽牌不同下的这一固定场景；城市专项另包含三组种子的五日日程。

医院集成用例实际移动、徒手搜索、结束回合、基础封装、返回入口、撤离、归队与日结交付，检查合同到账时点、唯一实物和工具次数。
