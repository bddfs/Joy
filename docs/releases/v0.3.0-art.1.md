# Joy v0.3.0-art.1 · 美术与界面候选试玩版

本版将美术与界面 v0.1 的 **P1–P5 候选实现**接入 M2 单城原型，供开发者试玩与团队评审。视觉方向尚未获得最终人工审美批准。

## 启动

从 [v0.3.0-art.1 GitHub Release](https://github.com/bddfs/Joy/releases/tag/v0.3.0-art.1) 下载 **Joy-v0.3.0-art.1-windows-x64.zip**，源码保留在 `codex/art-ui-v01` 实现分支。完整解压到可写目录后运行 **Joy.exe**。请保留全部随附文件，包括 `Joy.pck` 与 `data_Joy_windows_x86_64`。

Windows 64 位包采用自包含 .NET 运行时，无需安装 Godot、.NET SDK 或另装运行时。精确源码提交和运行时版本见包内 `build-info.json`；ZIP 校验文件 **SHA256SUMS.txt** 在同一 Release 的附件中，打包与解压验证范围见下方实施记录。

## 本版变化

- **P1 城市经营：** 七节点地图、独立归属与营业状态、共享工具预留及调度信息。
- **P2 旅馆现场：** 固定 2D 房间、门与出口导航、明确的真实照明状态；异常反馈只依玩家已观察到的事实。
- **P3 行动卡牌：** 三种候选插画与统一卡框，五槽用后留空，模仿参考、当前对象和耗尽状态分别显示。
- **P4 实物与工具：** 座钟、灯具、封装工具的统一主体缩图，实际位置、封装、余量和支援额度分开呈现。
- **P5 长文与反馈：** 常驻分区预览、事实/假说/已确认规程标记、护符抵挡与最终心志记录，以及按实际顺序展示的日结明细。

显示设置提供 100% / 125% / 150% 文字缩放、灰度与静态模式。保留 M2 经营、现场推理、灯具处置和誊写护符夹组合原型。

## 存档与首次试玩

继续使用 **v2 存档**，兼容已有 `user://profile-m2/save.json`，上一份完整备份为 `save.json.bak`。历史 `user://profile` 保留且不混读。继续游戏恢复最近成功保存的完整检查点；请以界面的保存位置和退出提示为准。旧档不补发后来加入的实物，体验护符夹投放请开新局。

首次试玩建议从不带传播压力的基础场景开始，自行阅读记录、提出假说，再用行动验证。反馈请附种子、经营日、房间、操作顺序、截图和 `build-info.json` 中的提交号；重点记录是否容易辨认真实位置、费用、照明、护符消耗和未知信息，以及大字号下是否仍能顺畅操作。无需查阅答案完成试玩。

## 验证、素材与范围

[实施记录](https://github.com/bddfs/Joy/blob/codex/art-ui-v01/docs/art/implementation-v0.1.md) 与 [客户端 QA 汇总](https://github.com/bddfs/Joy/blob/codex/art-ui-v01/output/art-ui-v01/qa/validation.json) 分别记录已实现、已检查和仍待人工评审的部分。核心自动回归为 **928 项通过、0 失败**；客户端 QA 脚本覆盖 59 个截图状态及 9 组未知 A/B 配对，执行结果以 QA 汇总为准。自动检查及截图不代表首次玩家推理、平衡或最终审美已经验收。

包内 `Art/assets.json` 保留本轮 AI 生成素材清单，`Licenses/AI-Art-NOTICE.txt` 保留来源及权利边界；Godot、.NET 与中文字体许可也在 `Licenses`。素材仍为候选，不将生成记录视为最终权利清理或团队批准。

这是单城开发原型，尚未提供完整三城远征与连续生成，也不是正式发行版本。本轮试玩包仅包含 **Windows 64 位**，不包含 macOS 构建。
